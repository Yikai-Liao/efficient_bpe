# 精确贪心 BPE 的并行架构选项

本文是设计探索，不是已实现或已测出的加速结论。目标契约是：每轮按全局加权相邻 pair 频率选择最大者，平手按既有 key 顺序；给它分配唯一新 ID；在整条连续 token 路径上按物理位置从左到右替换全部不重叠出现；产出的规则序列和最终 token 必须与单线程基线逐项一致。`0` 分隔符是永久边界。此处的“精确”还包括 `AA` 的左到右取舍，不能只比较最终字符或压缩率。[形式化 BPE 论文](https://aclanthology.org/2023.findings-acl.38/)说明贪心规则序列本身是有定义的算法对象；本文具体平手顺序和加权语义则来自本项目实现。

## 当前瓶颈与不可消去的顺序

当前 `parallel_occurrence_snapshot.rs` 每轮先取一个全局胜者，再并行验证其历史位置；主线程汇集有效位置并串行生成不重叠 plan；worker 并行写入，主线程汇总频率 delta；下一轮才能决定新胜者。`serial_select_seconds`、`sync_seconds`、`validation_seconds`、`apply_seconds` 已分别计量。把同一规则的替换分给四核，只能并行其中一部分；它不能消除每轮全局最大值和新 pair 频率的依赖。

设 `R` 为规则轮数、`M` 为实际替换数、`P` 为核数。在最坏的 `A…A` 长 run 中，刚生成的 ID 立即组成下一轮最优 `(X,X)`，依赖链可达 `Ω(R)` 轮。任意表示都至少要处理足以决定这条链的信息；这不意味着每轮所有 `M` 次替换必须串行。若四核达到整体 3×，理想 Amdahl 模型的串行占比至多 `1/9≈11.1%`，实际同步与缓存开销会把容许值压得更低。这是目标条件，不是对现有实现的速度预测。

## 三种真正不同的状态归属

| 架构 | 谁拥有主要状态 | 每轮必须同步什么 | 可能赢的负载 | 先失败的负载 |
|---|---|---|---|---|
| Pair owner | 按 pair key 分片频率、历史位置与局部 max heap；共享或独立的 corpus 由位置任务处理 | 各 owner 的候选最大值；选中 pair 的 occurrence 验证与全部 old/new pair delta | 高频 pair 分散，pair 更新哈希占较大成本，owner 分配均匀 | 单一热点 pair、低频长尾、跨 owner 随机更新 |
| Text block owner | 每个 worker 独占连续物理位置及其局部边界；频率先局部聚合 | 全局 key 频率与最大值；切块处的相邻 token、跨块合并归属 | 多个独立长区段同时命中胜者、局部性好 | 单段热点、长 token 穿过切块、全局 key 高度重复 |
| 有序多规则推测 | 全局已提交语料加小窗口只读 plan／delta 日志；按规则顺序认证提交 | 下一胜者、所有前驱规则带来的频率变化和相关边界版本 | 相邻若干赢家稳定且空间上弱冲突，认证能批量通过 | 新 ID pair 频繁跃升、`AA` run、相邻 `ABAB`、低频平局 |

### Pair owner：把索引并行化，不自动把替换并行化

`hash(key) mod P` 决定 pair 的频率、历史起点列表和局部 heap owner；arbiter 从 `P` 个局部最大值按 `(frequency, tie key)` 选择全局规则。选中 owner 可以把 occurrence 列表分段交给执行 worker，但 corpus 修改仍需位置所有权或一条规则内的不重叠 plan。每次替换会删除至多三个旧相邻边、生成至多两个新边（相邻替换需消重与纠正上下文），这些 key 很可能属于不同 owner。要精确选下一胜者，所有影响全局最高值的 delta 必须可见，或有正确的上下界证书；仅用各 owner 未更新的局部峰值会选错。

初始每个物理相邻边至少贡献一条频率记录／可重建来源；历史 occurrence 可以懒保留，总记录数按初始边加每次替换新建的边计，至多 `O(N+M)`，但哈希表、列表容量和 owner 队列会提高常数。若 owner 自存完整 corpus 副本，空间变为 `O(PN)`，不适合作为这里的基线。每轮至少需把活跃 owner 的候选和相关 delta 送到最终选择处；`Ω(P)` 是这种集中汇总设计的通信量条件，不是所有共享内存算法的普适下界。热点 pair 若只在其 owner 串行处理，吞吐上界立即落在单核；必须另行分摊其 occurrence 工作。

### Text block owner：保留局部性，但边界是动态的

按原始位置切连续块，worker 保存自己位置的 token 边界、局部 occurrence 和 delta 表；每轮广播同一个全局胜者，局部并行替换，再对 key 的 delta 求和。相邻 pair 的全局频率必须合并，不能让每块各自训练规则后拼词表。连续语料没有永久 `0` 的内部切点：固定 `H` 字节 halo 在 token 长度超过 `H` 时不再代表真实邻居。必须用可跨块的 token 边界描述、版本化跨块查询/迁移，或把跨块 token 的所有位置交给一个 owner。单个长 token 可以越过多个块，故“只与左右一块通信”也不是长期不变量。

若用真实 piece 边界切片，跨 piece 合并不存在，证明简单；但单个连续 4 MiB piece 会全落一块，没有并行度。若按物理位置切，`AA` run 在块界的左到右配对需要从前一块传入奇偶状态；`ABAB` 的两次替换虽不重叠，后者的左邻已变成前一次的新 ID。分块只减少常规局部访存，不能替代全局规则顺序。低频长尾时每轮工作量小，广播/汇总的固定成本可能盖过局部收益。

### 有序多规则批处理／推测：先证明赢家，后并行应用

规则的空间写集不相交只是必要的局部条件，不足以提前确定**规则顺序**。连续语料 `ABCABCABCDEDE` 中初始 `AB=3`、`BC=3`、`DE=2`（`AB` 在同频平手中先胜）。首轮 `AB→X` 后 `XC=3`，所以精确前两条规则是 `AB, XC`，不是在首轮快照上把互不共用符号的 `AB, DE` 一起选出。后一种 batch 的两个文本写集完全分离，规则序列仍错。[BatchBPE 原文](https://arxiv.org/html/2408.04653)以并行处理互不干扰的 token pair 为目标；该条件不能直接当成本项目“与逐轮贪心序列完全相同”的证书，论文也讨论了新 pair 对后续排名的影响。这一差别是本文从算法契约作的推论。

可行路径是一个小的有序推测窗口：从已提交状态取候选，只读预备 occurrence plan、局部边界版本和计数 delta；按原顺序验证每个候选是否仍为全局最高（含平手）并验证 plan 读集；只提交最长有效前缀，失败项丢弃并从新状态重算。日志按实际触及位置/边存储，不复制 `P` 份全语料。另见 [事务式推测设计](PARALLEL_RESEARCH_SPECULATION.md)。同一规则内部的左到右 path contraction 仍可用块级 scan/段摘要并行，但这与跨规则推测是两层不同并行度。

## 反例与评估判据

- `AAAAA`：原始 `AA` 有四条重叠相邻边，但只能取位置 1、3；切块后从局部位置“第一个”各自配对会改变全局奇偶。热点 `A^n` 还可使一个刚生成的 ID pair 持续成为下一胜者。
- `ABAB`：两条 `AB` 的 token 写入可以并行，第二条的左邻在规则完成后是第一条的新 ID；若独立生成旧边 delta，会把中间边漏算或重复扣减。
- `ABCABCABCDEDE`：空间互不干扰的下一旧 pair 被新 ID pair 跃升插队，否定只看位置冲突的多规则 batch。
- 一条跨块 token 长于 halo：固定宽度边界复制无法得知真实前驱/后继；动态 owner、远程边界记录或回退路径不可省。
- 所有候选频率接近阈值 2：历史列表小，`P` 个局部堆、广播和同步的每轮固定成本可大于替换计算。

对 4 核 3×目标，先用同一 release binary／fixture 记录每轮 `valid occurrences`、有效替换、每 worker CPU 与最长执行时长、全局选取/计数归并/认证/等待时间、跨 owner delta 数与字节、跨块边界事件、推测废弃率。可证伪假说是：若 4 MiB 连续输入的候选窗口通常无法认证两条以上规则，或不可并行的选取与认证超过单核总时长约 11%，那么仅增加 worker 不可能达到 3×；若大量时间确实在可分布的高频 occurrence 与索引更新上，且跨 owner 通信/重做很少，pair owner 或 bounded speculation 才值得做原型。观察到某一轮 3× 不等于端到端 3×，必须以 `call_seconds` 的同算法 1-worker 对 4-worker 比值与完全相同规则指纹检验。
