# 连续语料上的 worker 局部索引与批量 BPE

2026-09-30。原生实现版本为 `c2e8c69`；二进制和检查记录见 [checks.json](batch_results/checks.json)。本轮已经实现精确批量应用，支持不按空格预切分的单个连续序列。此前 [并行重设计](PARALLEL_RETHINK.md) 中的串行批宽探针仍保留，二者是不同实验。

初步结果支持继续沿这条路线优化：英文 16 MiB 上，精确实现从 1 核到 4 核为 **2.42×**，相对本轮两个直接串行版本中较快者为 **1.60×**；中文分别为 **1.88×、1.18×**。这些是单次诊断，尚未达到四核 3×，内存也有增加。完整重复矩阵已按迭代要求暂停，后续先用轻量基准筛选变体。

## 已实现的三个版本

核心在 [parallel_certified.rs](src/ablation/parallel_certified.rs)，选择入口是 `ablation --variant`。

| 版本 | 选择与应用方式 | 对照用途 |
|---|---|---|
| `parallel_certified_single` | 每批只选一个 pair，位置索引分散在持久 worker 中 | 隔离索引归属变化带来的收益 |
| `parallel_certified` | 从精确全局顺序取互不冲突的连续候选前缀，遇到第一个冲突即停止；上限 256 | 保持串行完整合并顺序的主线 |
| `parallel_batch_relaxed` | 跳过冲突候选继续找可合并项；批上限 256，候选扫描最多为上限的 8 倍 | 允许改变贪心顺序的近似对照 |

三个版本共用批次应用内核。精确版本保持 `(pair, weighted frequency, fresh ID)` 的完整顺序和最终 token；近似版只要求实际选中的 pair 频率准确、应用正确、跨 worker 数确定，不能与精确版要求相同 fingerprint。

初始化按原始位置区间分工，不往边界插入分隔符。整个训练器只有一份共享的 `AtomicU32` 端点语料，稳态载荷为 4N 字节。每个 worker 保存部分 `pair→Vec<u32>` 历史位置；新边的位置记录保留在生成它的 worker 上。同一种 pair 可以在多个 worker 上各有一个片段，但不会为每个 worker 复制完整位置索引。

初始化先并行计数，汇总全局频率后再并行扫描，只为达到 `min_frequency` 的 pair 建索引。不能先按各 worker 的局部频率过滤，否则会丢失全局高频 pair。

每批先在稳定语料上并行规划，直接产生批末的邻接边。比如相邻 `AB/CD` 同批收缩时，生成最终 `Zi/Zj`，省去中间曾存在的 `Zi/C`。共用边由左匹配负责，worker 本地聚合频率变化；协调线程只收 key 级 delta。所有读取和规划完成后才允许并行写入；写入完成后才开始下一批选择。

`AA` 重叠出现需要单独处理：当前仍将有效起点汇总、排序，按全局从左到右选非重叠匹配。它保证连续 run 跨工作区间时的正确性，但还保留串行位置工作。普通非 self 批次已移除协调线程逐位置组装计划的路径。

## 单次诊断的时间与内存

原始数据为 [pilot-v1b](batch_results/pilot-v1b/commands.json)，共 32 次新进程运行，使用同一默认 release 二进制、checked 访问、每项一次。以下以 `call_seconds` 计时，包含训练调用内的输入验证、初始化、合并和最终遍历；不含 fixture JSON 解析、输出指纹及写文件。VmHWM 是整个进程的峰值，包含计时区外的解析与输出分配。

本机是 6 vCPU KVM，暴露 Xeon Gold 6140 型号、单个 NUMA 节点。1 核运行固定 CPU 5；4 核运行将**整个进程（包括协调线程）**限制在 `[0,1,2,5]`。它不是双路服务器的扩展性验证。各环境 sidecar 保存二进制、源码、输入哈希及 CPU 配置。

每格为 **秒 / 峰值 MiB**；CF 为 `combined_filtered`，CF16 为 `combined_filtered_halfword`。

| 连续语料 | CF 串行 | CF16 串行 | 精确批次 1 核 | 精确批次 4 核 | 同实现 1→4 | 4 核相对较快直接串行 |
|---|---:|---:|---:|---:|---:|---:|
| 英文 4 MiB | 1.738 / 95.4 | 2.235 / 88.2 | 3.459 / 117.0 | 1.607 / 146.8 | 2.15× | 1.08× |
| 中文 4 MiB | 1.323 / 100.5 | 1.117 / 96.8 | 1.826 / 118.5 | 1.018 / 125.3 | 1.79× | 1.10× |
| 英文 16 MiB | 6.483 / 271.7 | 6.595 / 243.8 | 9.820 / 271.5 | 4.056 / 356.7 | 2.42× | 1.60× |
| 中文 16 MiB | 3.146 / 165.1 | 3.079 / 159.3 | 4.914 / 184.9 | 2.611 / 276.0 | 1.88× | 1.18× |

全部为 3,000 次合并选择、`min_frequency=2`。旧 4 MiB 连续 fixture 将同一 piece 的权重设为 2；新增 16 MiB fixture 权重为 1。因此只能在每行内部作线程或实现对照，不能把 4→16 MiB 当作仅改变大小的受控实验。权重 2 也使很多仅出现一次的初始 pair 达到过滤阈值。真实输入的固定来源见 [large-sources.json](ablation_results/large-sources.json)，原始快照和另一个 benchmark 工作区均未修改。

另外两个已有诊断：英文 1 MiB 段落输入，精确 4 核 0.504 秒、较快直接串行 0.553 秒；中文 4 MiB regex 输入分别为 0.526、0.479 秒。收益依赖输入结构，不能从连续英文推广到全部输入。

### 批量本身有多少作用

| 连续输入 | 单轮局部索引 1 核 | 精确批次 1 核 | 单轮局部索引 4 核 | 精确批次 4 核 | 近似批次 4 核 |
|---|---:|---:|---:|---:|---:|
| 英文 4 MiB | 2.904 s | 3.459 s | 1.634 s | 1.607 s | 1.198 s |
| 中文 4 MiB | 1.716 s | 1.826 s | 1.286 s | 1.018 s | 0.910 s |

单轮版本也取得了多线程收益，说明位置索引留在 worker 是本轮收益的重要来源。精确批次在中文 4 核诊断中进一步减少用时，英文两者接近；1 核时批次版本反而更慢。不能将全部加速归因于扩大批宽。

近似版本在这两个样本上更快，但 4 核峰值分别为 192.3、146.6 MiB，高于精确版本的 146.8、125.3 MiB。它改变词表选择顺序，质量尚未评估。已准备 [batch_quality.py](tools/batch_quality.py)：在相同实际合并数下，按训练前缀与不重叠的 heldout 后缀比较 token 数，并处理训练 piece 权重及未见字符。完整质量评分留到变体筛选之后，不以速度推断质量。

## 内存没有按线程复制，但片段元数据会增长

英文 4 MiB 上，精确批次在 1 核和 4 核的最终历史位置条目数均为 **4,841,871**，位置容量峰值之和分别约为 31.75、32.44 MB。与此同时，局部 map 条目总数从 **336,700** 增至 **630,486**，这是真实的碎片元数据成本。

已有常数优化把 `Plan` 从 40 字节收紧到 16 字节，把 `NewEdge` 从 16 字节收紧到 12 字节，均有编译期大小断言。它们是临时记录大小，不是总内存缩减比例。worker 的长度表、局部 delta map、保留容量的 scratch、线程栈，以及初始化计数表与 eligible 集合仍需计入。

指标中的 `index_*_peak_sum` 加的是各 worker 自己的峰值，可能并不同时发生；map capacity 是槽数，不能直接当字节。输入转原子语料时的分配行为也会影响初始化峰值。分项计数尚不能构成完整分配账本，端到端空间比较以 VmHWM 为准。16 MiB 英文并行峰值为较快串行的约 1.31 倍，中文约 1.73 倍；当前还不是最佳内存甜点。

## 复杂度与下一处瓶颈

令 N 为原始位置数，W 为 worker 数，H 为一批选中 pair 的历史起点总数，D 为 worker 局部聚合后的变化 key 数之和，K 为全局活跃 pair 数。初始化工作仍为 O(N)，两遍扫描换取少存低频位置；串行验证和协调线程的初始 key 汇总尚在。普通批次的位置工作为 O(H)，分摊到 worker，负载倾斜会限制加速。协调线程仍需 O(D) 汇总，再做受影响候选的堆更新；它没有随 worker 一起拆分。AA 汇总排序仍需 O(M_AA log M_AA)，广播删除 key 还有 O(W·D_drop) 成本。

历史位置的累计追加数量可由初始边数加每次实际替换至多两条新边约束到 O(N)，因为每次替换减少一个活 token。这个界约束条目数，不约束 Vec 过量容量、map 槽或峰值 RSS。单个 pair 可在多个 worker 上有 map 项，所以相同位置载荷并不等于相同索引总空间。

英文 4 MiB 从 1 核到 4 核，plan 阶段由 1.582 降到 0.589 秒，apply 从 0.832 降到 0.418 秒，而串行 reduce 仅从 0.377 降到 0.337 秒。plan 计时内还含协调层 delta 收集，不能再将其单独相加。16 MiB 英文/中文的 4 核 CPU 时间与墙钟比分别为 2.70、2.29，尚未充分利用四核。

下一候选是 [位置分片与 pair 标量双层归属](BATCH_OWNERSHIP_DESIGN.md)：位置留在物理区间，频率与候选堆按 pair 分散，worker 直接分组传递 delta，协调层只处理候选摘要；AA 用跨区间 run 奇偶前缀代替全局排序。这是设计，尚未实现或获得加速数据。外存、NUMA 和更紧凑并行语料布局也尚未实现。

## 正确性与迭代流程

此二进制已通过 37 项 Rust 测试、Clippy 和 1,792 次独立 Python recount 完整轨迹对照，涵盖精确两个版本、1/2/4/6 workers、checked/unchecked。测试包含跨区间相邻匹配、AA、加权极值、长 span、同频和新 key 抢占。近似版本另有逐次重放验证及跨 worker 确定性检查。只读审查未发现具体相位或越界错误；这些检查不等于 Miri 或 sanitizer 验证。记录见 [checks.json](batch_results/checks.json)。

后续每次小改动只做对应正确性检查和轻量性能筛选，不重复整个历史矩阵：

| 模式 | 默认内容 | 用途 |
|---|---|---|
| 无模式参数 | 英/中各 256 KiB 连续输入、512 轮、CF 串行与精确/近似的 1/4 核，共 10 次，每项 1 次 | 快速筛选；本机已跑通，测试阶段共 1.47 秒 |
| `--smoke` | 英/中各 4 MiB、3,000 轮、CF 串行与精确 1/4 核，共 6 次，每项 1 次 | 少量检查多线程方向，避免小样本开销掩盖收益 |
| `--pilot` | 本轮 4/16 MiB、连续/预切分和单轮/近似的 32 项诊断 | 候选初步收敛后扩大输入范围 |
| `--full` | 扩展线程数、每项默认 5 次 | 变体全部对比、收敛后的最终矩阵 |

`1.47 秒` 是两个 benchmark 子进程阶段合计，包含各次启动和结果校验，不含前置 fixture 生成、哈希预检，也不含编译。quick 单次数据不用于报告服务器扩展性。精确版本与串行比较指纹，近似版本单独核对跨 worker 指纹。`--variants` 可在 quick/smoke 中只运行当前候选。

从仓库根目录，先在原生代码改变后增量构建，再运行：

```sh
cargo build --manifest-path rust/Cargo.toml --release --bins --locked
python rust/tools/run_batch_matrix.py --output-dir rust/batch_results/reruns/try-01
python rust/tools/run_batch_matrix.py --smoke \
  --variants parallel_certified_single,parallel_certified \
  --output-dir rust/batch_results/reruns/smoke-01
```

数据生成只读取已有快照。每次用新输出目录，保留命令、哈希和原始结果。[formal-v1](batch_results/formal-v1/INTERRUPTED.json) 是收到轻量迭代要求后主动中断的不完整矩阵，已排除于本报告；不会混入 pilot 或未来正式统计。
