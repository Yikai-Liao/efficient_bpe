# 微区、producer 减频与全局有序 posting：同窗小测

这轮实现了三个独立 Rust 原型，全部保持串行 greedy 的规则顺序、加权频率和
最终 token。没有发现足以切换默认实现的通用速度收益，也没有达到四核 3×。
最值得继续使用的是**全局有序 posting 的不变量**：它消除了 AA 的最前排序，
并为按本批工作量移动 cut、压缩和顺序读取位置表提供前提。这里的结构收益
不等于已经测得明显提速，更不等于已完成外存训练。

三个实现由 Sol 分别开发和审查，统一 executor 运行 Cargo、独立 oracle 和
56 次计时。root 审查证明、并发边界与归因。本轮没有运行完整旧矩阵或 4 MiB。
所有原始时间、CPU、训练 VmHWM、完整轨迹核对、源码/二进制/fixture 哈希及
可复现脚本在[同窗归档](batch_results/radical-micro-atomic-ordered-v1/README.md)。
共享依赖基于提交 `e2cfd89950f6b80cd4cad229737979417f4ff04a`，新 crate 单独封存。

自然语料是连续 EN/ZH 各 256 KiB、512 条规则、weight=1/min=2、aHash/lazy，
chunk=4096。W1 绑 CPU 5；W4 的整个进程（包括协调线程）绑 CPU 0/1/2/5，
不能借第五个核。报告训练完整调用，含输入验证、建池、建索引和最终扫描。
除自然语料的 ordered 比较 n=1 外，其余格 n=2，取中位数并保留两次原值。
这些只是筛选，不能外推几十核、NUMA 或其他语料规模。

公平的直接串行 CF32/aHash/checked 同窗为英文 **37.55 ms**、中文
**19.85 ms**。例如 producer-atomic W4 相对它仅为 0.91×/0.88×，全局有序
W4 为 0.98×/0.95×。不能只对自己较慢的 W1 算比例，而忽略直接串行。

**微区：负载改善是真的，净收益没有。**
[实现](experiments/radical/owned_region_tasks/DESIGN.md)将物理区数设为
`T=min(kW,N)`，pair owner 仍为 W；每个区独占端点范围，切点可以穿过 token，
snapshot 的跨区写在 join 后回放。没有每线程一份全局索引。
对非 AA 等成本访问，逐批调度时间至少为
`max(ceil(total_visits/W), max_task_visits)`。总访问量除以这些下界之和，
英文 k1/k4 为 **3.69/4.00**，中文 **2.64/3.56**。这只是访问工作模型的
速度上界，不是实测阶段时间，AA 的扫描/排序也不按这个任务划分。

W4 的 k1→k4 使位置二分次数 4096→16384，route 头容量载荷
1408→5632 B，snapshot 窗口描述符 600→3000 B。局部聚合表公开 capacity
峰值英文 7168→14336、中文 3584→5152。它们不等于物理 bucket 数或 allocator
实际字节，不能据此单独计算总内存。实测 region 训练 HWM 英文约
8.96→9.59 MiB，中文约 8.25→8.26 MiB；没有节省内存的证据。扫描量不变，
额外区间定位、更多局部键和提交工作吞掉了均衡收益。因此不继续盲扫 k。

**Producer 原子减频：把工作搬过去，没有消除它。**
[协议审查](PRODUCER_OLD_REDUCTION_REVIEW.md)让每个 producer 完成本地
聚合后，对每个旧 key 至多做一次原子减法；owner 字典整个阶段结构冻结。
只有唯一跨过 min 的操作保留原 route 记录作退休标记。join 后 owner 删除
这些项，不能再扣一次；fresh 归约和填充仍保留原屏障。两模式 Entry 均为
24 B、posting 为 16 B，没有新增每 worker 索引或每 Entry 字段。

W4 英文每次约 3.28 万旧局部记录变为 4299 个 owner 退休标记，producer
实际执行约 2.98 万次原子减法；中文约 1.53 万记录变为 3748 个标记，
约 9577 次原子减法。记录少了，但 producer 多了共享表查询、retain 扫描和
原子缓存一致性工作。英文 plan 中位数 12.05→16.98 ms，中文 5.74→6.17 ms。
`atomic_flush_worker_seconds_sum` 是各任务时间之和，已经包含于 plan/AA
route 路径，不能再加到 wall time 上。

owner 控制会在跨阈值后立即删除，atomic 模式要等 join 才删，所以两者的
旧键命中次数本来就可能不同。动态任务分派也使局部聚合记录数在重复运行间
略变。比较的是最终完整轨迹和全调用，而非强求这些中间计数相等。删除 route
条目不保证释放其底层分配，本轮 HWM 差异不足以确立内存优势。eager 请求
明确回退 owner，不能把该路径算作验证了另一套原子堆发布协议。

**全局有序：用出生来源的唯一性代替排序。**
[证明与实现边界](ORDERED_POSTING_REVIEW.md)利用每个 fresh key 由唯一
一条规则的一个方向产生；该规则在区内按升序遍历。跨区左 birth 是目标区
最后一条活邻边，join 后追加仍有序。出生链本来反向链接，owner 仅反转刚
追加的 `(region,key)` 片段，再按物理 region 顺序连接。全部额外反转工作
累计 O(N)、额外空间 O(1)，不再对 AA 历史位置作比较排序。原 route map、
8 B BirthNode 和位置表分配仍存在，整个训练并未因此变成 O(N) 时间/O(1) 空间。

自然英文实际省去 1 次、250 项 AA 排序，却反转了 269984 个出生位置；
中文省去 11 次、1389 项排序，反转 40975 个位置。控制的 AA 排序仅
0.007/0.095 ms，远小于自然语料全调用差值。因此不能把 n=1 的改善全部归因
于省排序；位置访问顺序、其他阶段和噪声都变了。W4 填充阶段分别从
3.93→4.50 ms、2.10→2.40 ms，也说明反转不是免费操作。

在专门激活 AA 的 AB 64 KiB 输入中，全局模式确实省去 15 次、65519 项排序，
排序阶段从约 1.09 ms 归零；全调用中位数却只有 11.40→11.25 ms。
控制两次为 8.72/14.09 ms，全局为 11.63/10.86 ms，区间明显交叠，不能宣布
稳定提速。没有推广为速度默认，但保留这个有证明、无需新增索引的结构基础。

正确性验证共 **66 项 Rust 库测试**，三 crate 的 fmt、strict Clippy、release
均通过。独立 naive oracle 完整对照分别为微区 92 次、原子 85 次、有序 90 次，
合计 **267 次**；另外有微区 k1 的 8 组新旧二进制对照、有序 dynamic/global
拒绝检查。56 次计时的完整规则、频率和最终 token 也全部匹配。测试覆盖
AA→非 AA、相邻 fresh/fresh、长 token 跨多个 cut、非均匀/大 u64 权重、
snapshot 延迟写、W>N 和 tagged ID 域回退；它们不替代 Miri 或并发模型验证。

下一轮保留两个不同层面的方向，均尚未实现：

- [按工作量选 cut](ADAPTIVE_ORDERED_CUTS_NEXT.md)：全局有序后，可只用
  O(BW) 元数据按最长表分位或全表 rank 样本选约 W 个区，复用范围二分结果。
  它避免靠增加 T 换均衡；误差界仅针对历史访问，不能保证有效改写成本均衡。
  首版针对 atomic region，snapshot anchor 重建仍需独立方案。
- [有序位置表压缩](ORDERED_POSTING_STORAGE_NEXT.md)：密集长表使用 u16 gap
  和 u32 escape，短表保留内联；必须把 checkpoint、对象头和构建时双份峰值
  一起计入。当前没有压缩实测，也没有磁盘预算保证。

另在审查一种[更大的内存折衷](REPLAY_BIRTH_FILL_NEXT.md)：首遍只累计出生数量，apply 后重读选中历史表，
直接填 owner 分配好的有序区段，从而完全去掉出生链。它可能以第二遍检查和
额外同步换掉 8 B 节点，需要单独证明跨区填充、对象地址稳定和错误时析构；
目前不能把它计入已实现或已测收益。
