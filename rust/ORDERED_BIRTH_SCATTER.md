# 用计数与分段填充建立有序出生位置表

这是全局不可变 posting 路线的后续设计，目标是替换首版对出生边 `(key,pos)` 的比较排序，并将初始化和位置填充交给多个核。实现与速度尚待验证；本文件记录可以依赖的顺序性质和空间代价。

## 顺序其实已经存在

先限于原型当前一次提交一个 `AB→Z` 的情况。AA 使用全局左到右奇偶选中后，也适用下述条件：完整 Plan 序列按原始起点递增，匹配区间互不重叠；各 chunk 是该序列的连续区间；邻接的新边直接按最终替换结果生成，两个相邻匹配的共享边只由左匹配产生。

本轮新 key 只有三类：

| 新 key | posting 起点 | 为什么在 Plan 顺序中递增 |
|---|---|---|
| `(L,Z)`，L 是未替换的旧 token | 当前匹配左邻 token 的起点 before | 两个不相交匹配的左邻起点保持原文顺序；若左邻也被选中，该边被共享边规则抑制 |
| `(Z,R)`，R 是未替换的旧 token | 当前匹配起点 pos | Plan 按 pos 排序 |
| `(Z,Z)` | 左侧匹配起点 pos | 同上，共享边只产生一次 |

因为 Z 是全新 ID，第一类和第二类不可能碰巧成为同一个 key，第三类又有唯一的左匹配生产者。因此，**固定 key 在每个 chunk 内已经有序，按 chunk 原始顺序连接后也有序**。不必按 `(key,pos)` 再作全量比较排序。

这个结论依赖 chunk 保留原文位置顺序。不能按任务的完成时间或工作线程编号连接结果；动态调度完成顺序没有这个保证。空 chunk 只是没有记录，不打断逻辑顺序。若以后支持一批多个生成规则，要重新明确每类新 key 的生产者和 chunk 排序约定，不能直接沿用这里的单规则证明。

## Count → prefix → scatter

1. 各 chunk 独立遍历自己的出生记录，计算每个 key 的**物理记录数**。记录本身仍留在该 chunk 的缓冲中。
2. 按 key owner 汇总各 `(key,chunk)` 计数。owner 决定全局加权频率是否达到阈值；只有合格 key 分配新 posting 区间。对固定 key 按 chunk ID 求前缀和，为每个生产 chunk 分配独占子区间和起始 cursor。
3. 各 chunk 再按自己的原始记录顺序扫描，用该 key 的 cursor 写入它的子区间。不同任务的输出区间不重叠；固定 key 的子区间按 chunk ID 排列，故最终 span 有序。
4. 全部填充完成后才能发布新 posting descriptor，供下一轮只读访问。冻结之后不再追加这个旧 key 的位置。

不需要将所有出生记录先搬到协调线程，再由它逐条 scatter。协调者可以只给 owner 的总区域做一次小前缀和；每个 owner 自行分配其 key 区间。元数据归并及 chunk 排序仍是实际工作：若使用无序消息，必须按 chunk ID 恢复顺序，不能宣称它天然免费。

加权频率与物理记录数是不同量：一条 weight=10 的边只占一个 `u32` 位置。当前稳定快照、直接产生最终邻接的单规则实现中，新 key 的加权频率应等于其出生记录权重之和，可用来核验计数；不能拿加权频率当分配长度。历史 span 在后续轮次会含失效位置，不改变出生时的物理计数。

## 初始化可以用相同结构

初始输入按物理位置划成有序块。每个块局部计数 `(key, frequency, count)`，按 key owner 汇总、决定阈值，再为 `(key,block)` 分配独占子区间。各块第二次按位置递增扫描并填入自己的区间，得到每个 key 的全局有序 posting。

局部计数/offset 表只服务初始化，不成为每个 worker 的常驻历史索引。它可能有多份相同 key 的临时元数据；必须记录总条目数和同时存活峰值，不能因为最终 posting 只存一份就忽略初始化峰值。

## 复杂度、内存与 unsafe 边界

设 M 为本轮出生记录数，D 为出现过的 `(key,chunk)` 组合数，P 为本轮新 key 数。记录扫描与填充为 O(M) 工作，额外元数据为 O(D+P)。元数据归并、按 chunk ID 排序和偏移分配另外计量；若局部表使用哈希，O(M) 查找成本是通常的期望界。方案消除的是 M 条完整记录的比较排序，不保证任意输入的端到端时间为线性，也不预报加速比。

出生记录已有缓冲，计数/offset 表是额外空间。过细 chunk 会增加 D，太粗则限制负载均衡；应比较工作量、元数据与核利用率的折衷，而不是固定对某个语料调最优 chunk_size。

若直接并行写入同一 arena，可用安全的互不相交切片，或在局部封装中使用 `MaybeUninit<u32>` 与受控原始指针。unsafe 所依赖的条件必须逐项成立：所有总长度与前缀和已检查溢出；每个 descriptor 位于已分配区域内；不同 `(key,chunk)` 区间不相交；写入数量恰好等于其 count；扩容在分发指针之前结束；完成屏障之前不创建可读取未初始化元素的引用；出错时不发布部分完成的 span。

可对照的版本应保留首版排序、v2 chunk Plan 不展平，以及本方案三种结构。完整 rule/frequency/final 对照覆盖 AA、跨 chunk 相邻匹配、空 chunk、加权边、阈值过滤和大长度。性能比较要把计数、偏移元数据、填充和排序的实际时间分开，再看完整调用和 RSS。
