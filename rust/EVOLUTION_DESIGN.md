# 原生演进：表示、索引与并行之间的取舍

本轮目标是找到能在多种语料结构和规模下解释的速度—内存折中。没有指定的数据集、RAM 上限或 CPU 数需要拟合。当前实现和实验面向精确贪心 BPE：每轮选全局最高加权重叠邻接频率，同频按 pair ID 排序，然后从左到右做不重叠替换。所有轮次都分配 fresh ID；输出整数规则和最终序列，不物化每个 token 的完整字符串。

代码和实验属于训练核心。数字 Prepared 输入、JSON 解析、文本去重和分词的口径分别保留；全文单 piece 的案例保留空白和标点，不能拿 regex 分片的更低工作量解释成相同训练任务加速。实测结论见 [ABLATION_REPORT.md](ABLATION_REPORT.md)，全部版本映射见 [ABLATION_COVERAGE.md](ABLATION_COVERAGE.md)。

## 表示与复杂度

设 U 为物理位置数，R 为物理替换总数，K 为规则数，G 为权重段数，P 为候选堆的最大规模。R ≤ U，每次替换最多产生两个新的 occurrence 记录，故初始记录加累计追加记录为 O(U+R)。每条旧 pair 的历史列表只在其出队时遍历；fresh ID 保证旧 pair 不会重新增加。懒堆刷新按已发生的频率下降摊还，变化次数为 O(U+R)。在定长机器整数、哈希期望 O(1) 下，堆版核心的保守界仍为：

`O(U + (U+R) log(2+P) + R log(2+G))` 时间，`O(U+K)` 个定长槽位及哈希/容器开销。

最后一项来自每个替换位置对权重段的二分。真实预处理还至少读 N 个原始字符，若导出全部 token 字符串，另计输出字符总量 D。这里没有把局部表示替换称作新的期望线性训练算法；完整 Re-Pair 的全局位置重组和专用队列证明并未迁入这个共同驱动。

| 语料表示 | 逻辑缓冲字节 | 邻居/替换成本 | 限制或代价 |
|---|---:|---|---|
| 端点 ID | 4U | O(1)，lean 写 2/3 处 | 共享 token 长度表另计；查询契约针对历史 pair 起点 |
| 数组链 | 12U；附 run 槽为 16U | O(1) | 本移植不做 RLE；signed i32 links 限制位置数 |
| u32 位图 | 4U + 12⌈U/64⌉ | O(1) | 起点位图和空块跳距 |
| 半字位图 | 2U + 12⌈U/64⌉ | O(1) | 初始 alphabet ≤65535，fresh ID 可超过 u16 |
| H3 | 3U | O(1) | u16 ID 槽加方向 tag；长长度利用已吞并槽位 |
| H2.5 | 2U + ⌈U/2⌉ | O(1) | nibble 读改写，短长度直接编码范围更小 |
| ByteSpans | U | O(1)，只管边界 | 不含 token 身份，不是完整训练后端 |

`full_clear` 保留整段写零，额外写入量为各次物理替换跨度之和 ΣL，可为 Θ(U²)。端点、链、位图和 Hybrid 都避免这项。native memset 能降低常数，不能改变长链的增长阶。

Rust 的 `(u32,u32)` 和 `u64` 都占 8 字节。`packed` 的收益若存在，来自哈希和比较路径，而不是 Python tuple 对象那种大幅空间压缩。类似地，拆开和融合邻居读取的代码会被 Rust 内联和公共子表达式消除，必须用 native 的 unfused/fused 消融判断剩余收益。

## 索引往往比语料数组更值得优化

`combined` 把频率和 occurrence Vec 放进同一条哈希记录，减少为同一个 pair 查两张表。它的记录更宽，对大量低频 pair 也可能浪费空间。`combined_filtered` 因而先计数，只为初始合格 pair 创建最终记录；筛选安全性来自旧 pair 的频率以后只会下降。新 pair 必须等本轮贡献全部累加完再筛。

`separate_counted` 和 `combined_filtered` 使用同一种临时计数流程，隔离两表/单表差异；`filtered` 和 `separate_counted` 则隔离保留计数表/重建最终表的差异。共同驱动的全局规则、历史位置和 tie 规则完全相同。

Arena 用连续的 `(position,next)` 两个 u32 槽替换大量独立 Vec，回收处理完的槽位和 pair state。每条 occurrence 的逻辑槽从 4B 变为 8B，但可能减少小容器、容量余量和分配器成本。因此它不是无条件的空间压缩。`arena_counted` 在分配 state 前排除稀有初始 pair，避免先建大池再释放的高水位。

内存指标必须按口径读取：语料逻辑缓冲不是进程峰值；capacity 包含预留；Arena occurrence 槽数是池的高水位，而普通 Vec 统计的是当时保留的元素。正式总内存比较使用进程 VmHWM，包含 Prepared/JSON 加载的峰值、转换中的临时缓冲、哈希表、线程和分配器；它不是“纯算法常驻内存”。

## 长度超过 255 而边界数组仍为 U 字节

ByteSpans 对短 token 在两端保存有方向的长度 tag；长 token 的两端改为转义 tag，把完整 u32 长度的五个 7-bit 数位写入各端附近已被吞并的位置。内部 payload 使用与边界 tag 分离的编码，旧右起点与旧左终点失效，历史内部位置不会被误认成活起点。长 token 至少有 64 个原始槽，足够保存两端 payload；不需要外部溢出表，也不扫描整段。

因此边界组件仍恰好 U 字节，长短操作都为固定字宽下的 O(1)，长度可跨越 255 和 65535。代价是多次编码/解码和写入。它保留了原 v1 的一字节边界预算，但没有消除 v1 原文切片、字符串哈希或 token 身份索引的成本。对整数 ID 训练，4U 端点和紧凑 ID 布局是另一组可直接运行的选择。

## 并行的切分单位是本轮替换，而非永久文本边界

完整 piece 所有权能安全并行，但前提是语义本来就禁止跨 piece 合并。任意在连续文本插入边界会改变规则，例如 `aaa|aaa` 的 AA 匹配相位不能各自从头开始。连续版本不插入分隔符，只分配本轮候选 occurrence 的处理任务。

第一版 `parallel_occurrence` 用串行稀疏 overlay 推演每次替换后的上下文，再并行执行不相交写入。第二版 `parallel_occurrence_snapshot` 在稳定语料上并行验证；A≠B 的有效匹配天然不共享 token，AA 则按全局从左到右选交替边。协调线程修正相邻匹配的左上下文，再派发不相交跨度。`ABAB` 中短暂生成、随后删除的新边也会保留与串行相同的计数和历史记录。完整不变量和原子访问证明见 [PARALLEL_DESIGN.md](PARALLEL_DESIGN.md)。

第三版 adaptive 在小轮直接由协调线程更新，省掉验证和应用两个屏障；大轮沿用第二版。固定粒度 256/1024/4096 只是工作量消融，输入名称不参与分支。小轮仍先收集 delta，再通过共同 reducer，因此它尚未获得单线程直接更新的全部常数优势。

每轮有全局选规则依赖。快照方案的时间可拆为选规则、验证、串行选择、最慢 worker 应用、串行汇总及同步；`sync_seconds` 包含在验证/应用里，不能再次相加。更多线程只缩短其中可分配的部分。所有线程会工作与整体更快是两个不同的检验，报告同时比较同算法 1→多线程和多线程→直接单线程基线。

紧凑表示与并行还有一个实际耦合：不相交 token 的 H2.5 tag 可能共用同一字节，半字后端的活位图可能共用同一机器字。将这些结构直接改成普通共享写仍会竞争。可选方案是按元数据字所有权分配写入，或每个 worker 生成按块掩码再归并；原子按位操作也可保证正确，但需要测缓存行争用。本轮连续并行采用 AtomicU32 端点，尚未声称紧凑后端已同样并行化。

## 后续值得验证的架构方向

实测扩展不足后新增了 [跨领域重设计与批次证书](PARALLEL_RETHINK.md)，原生探针已显示真实输入约 11–14 条规则可形成一个安全前缀。优先验证整批最终邻接和局部索引的结合；下面的 pair 所有权路线仍是一个待比较的选项。

针对实测的串行占比，可以把 pair 频率和候选队列按稳定哈希分给所有者线程，worker 按目标 owner 聚合 delta，各 owner 更新本地队列，最后归约少量局部最大值。它能减少单协调线程的哈希工作，但会增加交换缓冲、跨 NUMA 通信和屏障。必须维持新 pair 的位置顺序及同频全局规则，不能只合并局部词表。当前代码尚未实现该路线。

较小的常数实验可以先隔离 delta 宽度：当前 worker 为了覆盖合法 u64 权重，统一用 i128 差分。若验证阶段已证明初始加权总边数不超过 i64::MAX，则整个训练的计数差分也可用 i64；超出时保留 i128 路径。这是按数值范围选择表示，不依赖语料名称。在当前 ABI 下，它有机会将 `(u64 key, i128 delta)` 的 32B 载荷改为 16B，但需另测哈希表、归并及峰值内存，不能直接从结构大小宣称吞吐翻倍。

AA 匹配也可进一步研究 run 前缀奇偶扫描：每块报告首尾 run 长度和是否跨块延续，通过小规模前缀归约确定每块初始相位，再并行挑选交替边。这针对快照版剩余的串行选择；相邻匹配的上下文仍需稳定快照或明确的边界摘要，不能一边读旧上下文一边无约束写入。若串行 reducer 更大，先实现此优化未必最划算。

外存路线应把数据分为两类：语料表示和 occurrence 记录按稳定块编号保存在磁盘，当前活跃 pair 计数、局部最大值及块目录留在内存。每轮按选中 pair 的 occurrence 所在块聚合访问，将邻接变化写成顺序 delta 日志，周期性归并索引。跨块 token 要保留全局端点身份；单纯把文本按行独立训练会改变任务。

这条路线需要额外控制活跃 pair 表、历史位置和日志的增长，并明确 I/O 摊还条件。mmap 只能改变载入方式，不能保证内存预算；每条规则重扫全语料则会增加 O(KU) 工作。目前没有实现或测量外存训练器。原生结果将决定下一轮先投入索引分区、批量归并还是外存日志，而非先绑定某个数据集与机器配置。

单块 u32 位置还有规模上限，当前公共输入要求 U < 2³²。更大语料可研究“块目录 + 块内 u32 偏移”，让一组 occurrence 共用块号；直接把每条位置扩大为 u64 则会增加主索引的空间。如何让分块索引同时服务内存和磁盘，是后续接口设计的一部分，当前原型没有隐式解决这个上限。
