# 按本轮实际参与者调度精确 BPE

当前分片版本已把频率与堆更新交给 pair owner，但每轮仍广播 Prepare、Reduce、Apply，并重新预取各 owner 的候选。这使少量位置变化也付出与总线程数 W 相关的控制成本。在 `chain-2000` 的单次诊断中，1,999 轮各只做一次替换；四线程分片版交换约 80,000 条消息、弹出约 249,690 次候选，耗时 0.390 秒，同版单线程为 0.118 秒。这个输入需要逐轮依赖，增加线程不能创造更多独立替换工作。

实验 `parallel_sparse_owner` 保留严格单轮选择，先验证候选缓存与稀疏调度；不与批次宽度、Plan4 合并为一个未经隔离的改动。以下是实现契约，已完成的轻量结果见 [归档](batch_results/sparse-owner-v1/README.md)。

## 两个可复用的不变量

**pair 的位置片段在出生时就能确定。** 本项目每次合并分配全新 token ID。每条新邻接边必含当轮 fresh ID，因此已经存在的 pair key 不会新增出现，只会失去出现。初始 pair 的持有者由初始扫描决定；新 pair 的持有者由其出生轮中真正生成 `NewEdge` 的 worker 决定。把这些 worker 的位取 OR，就得到在该 key 整个生命周期内有效的历史位置片段目录。即使部分位置后来失效，也不能漏掉任何待验证位置。这个性质依赖 fresh ID 语义，不直接适用于复用旧 ID 的实现。

**未受影响的 owner，其严格最高候选仍然有效。** 一个 owner 的 pair 表只会因为发给它的 delta 改变。若本轮没有这样的变化，它上一完整轮发布的最高频候选无需重算。收到 delta 的 owner 必须先汇总全部发送者，再应用变化、清理堆顶并发布严格最高值。发布的是验证后的精确频率，不能将惰性堆中的旧上界直接作为候选。

这两个性质分别消除位置阶段和标量阶段对所有线程的例行通知。频繁 pair 若遍布所有位置分片，仍然使用全部 worker。

## 状态与元数据的归属

每个持久 worker 同时拥有一份历史位置片段索引和一部分 pair 标量表。标量条目由原来的 `frequency: u64` 增为 `{frequency: u64, holders: u64}`，增加 **8 字节/key 的载荷**；哈希表实际容量和对齐仍须测量。语料、位置索引和频率表均不按线程完整复制。

64 个以内的 worker 每位对应一个 worker。超过 64 时，令 `group_size=ceil(W/64)`，每位对应一个连续 worker 组。置位与展开始终使用相同映射；这样每个目录仍是 8 字节，可能多唤醒同组的闲置 worker，但不会漏掉真实持有者。一个置位最多展开 `ceil(W/64)` 个 worker。分组只是保守调度，不插入文本边界，也不改变合并结果。[分组实现](src/ablation/worker_groups.rs)包含边界与覆盖测试。

协调者保留 W 个 owner 的严格最高候选。只有 owner 发布新候选时才更新全局堆；旧条目按 owner generation 作废。堆条目数超过 4W 时，从当前缓存重建，将存储限制在 O(W)，重建工作摊销到先前的更新。单次读取全局最高值不弹掉有效候选；该 key 被应用后，会由其 owner 的频率更新使之失效。因此单轮路径不需要候选租借、预取 32 项或归还未选项。[候选前沿实现](src/ablation/sparse_frontier.rs)用 5,000 次随机更新对照完整扫描，覆盖最高值下降、上升、删除及同频顺序。

token 长度表共享为 `Arc<RwLock<Vec<u32>>>`。协调者在派发本轮计划前持写锁追加 fresh ID 长度；规划 worker 在整个只读阶段持一次读锁，内部查询直接读切片，每次长度查询不加锁。它必须先释放读锁，再报告 Prepared。现有阶段屏障保证下一轮追加前已经没有规划读者，因此写入不与计划读取竞争。闲置 worker 无需补齐错过的词表更新，长度载荷也从约 4WV 降为 4V；锁及 Vec 容量另计。

## 单轮协议

1. 从缓存前沿选全局最高频、同频 key 最小的 pair。保存它的频率与持有者目录，分配 fresh ID；候选本身仍保留在 owner 堆中。
2. 只向目录展开的 worker 派发 Prepare。它们读取稳定语料，验证自己的历史位置，生成计划、新边和局部聚合 delta。路由在 producer 内直接送至相应 pair owner；回复协调者的是统计，目的 owner 集合通过共享 `AtomicU64` 取 OR 记录。无需协调者逐 key 汇总。当前每个非空目的桶执行一次原子 OR；后续可以改成 producer 内先取 OR、随回复携带位图，以减少共享缓存行写入，尚未实施。
3. 全部参与规划者回复后，向目的 owner 集合派发 Reduce，并强制包含选中 pair 的 owner，以检查其频率确实降为零。owner 汇总完整本轮 `i128` delta 后，才决定新 pair 的全局阈值和旧 pair 的退休。未跟踪旧 key 的负 delta 可忽略；正 delta 是不变量错误。
4. owner 将退休 key 直接投递到其目录指向的 worker 的 prune 邮箱。**低于阈值的 fresh key 也要通知其临时位置生产者**，否则会在位置索引里留下没有全局标量的片段。owner 向协调者回复严格新堆顶和 prune 接收者位图。
5. 全部参与 Reduce 的 owner 回复后，只向 `规划者 ∪ prune 接收者` 派发 Apply。它们删除退休片段、过滤不合格新边，并完成本轮不相交端点写入。只有修剪任务的 worker 不执行替换。所有参与者回复后，协调者才允许使用新前沿进入下一轮。

AA 保留已有精确回退：仅从 holder 集合收齐有效起点，但仍全局排序并从左到右选择非重叠匹配，再分发 selected 切片进行规划。不能让各 holder 独立消除重叠。新边的出生目录根据这次真正执行规划的 worker 重新形成，而不是继承旧 AA 的目录。

每条阶段命令与临时邮箱数据必须对应明确 epoch。位置 worker 保存 plan epoch，Apply 后消费或清空计划及新边；prune-only worker 不得重放上一次活跃轮的计划。分组位图带来的假阳性派发必须是空工作，不能变成额外替换。

## 为什么仍与串行一致

以已完成 Apply 的轮次作归纳边界。初始分片汇总给出每个 pair 的精确全局频率，各 owner 发布严格最大值，因此前沿第一次选出的 pair 与串行一致。

若某轮入口状态一致，固定持有者目录涵盖所选 pair 的全部历史记录，且没有其他地方新增过这个旧 key 的位置。普通 pair 的有效匹配互不重叠；AA 的全局从左到右选择覆盖串行重叠语义。因此这一轮修改的位置和新 ID 一致。完整 delta 汇总后，所有受影响 owner 的频率与串行一致；其他 owner 的频率未变。退休通知覆盖全部历史片段持有者和不合格新边生产者，Apply 完成后索引继续满足覆盖不变量。刷新过的最高值与未变的缓存最高值共同给出下一轮严格全局最大值，归纳成立。

必要反例：`ABC` 与 `AB` 两个 weight-1 piece 使 `AB=2, BC=1`。先合并 AB 后，BC 消失，产生 ZC=1；若 BC 的 owner 没刷新缓存，就可能错选已不存在的 BC。若阈值为 2，ZC 的 provisional 位置还必须被过滤。另一个反例是 AAAA 的 AA 起点 1/2/3 跨线程分布：分别局部选取可能同时选 1 和 2，只有全局左到右选择才得到 1 和 3。

## 成本、收益与边界

令 H 为选中历史位置数，A_p/A_o/A_a 分别为本轮实际派发的规划、标量归约、写入/修剪 worker 数，D 为发送至 owner 的局部聚合 key 记录数，F 为退休 key 的片段接收者数（含分组假阳性）。普通非 self pair 的位置工作为 O(H)，AA 的全局排序仍需 O(H log H)；归约工作 O(D)，控制消息目标为 O(A_p+A_o+A_a)，候选前沿更新为摊销 O(A_o log W)。修剪投递是 O(F)，不能隐藏成只与全局退休 key 数相关。上述 A 也包含 W>64 分组带来的假阳性。

路由也必须只遍历触及的目的 owner，不能给控制层省掉广播后，又在每个 producer 内扫描 W 个空桶。可以复用分桶数组并记录非空桶 ID；需要同时计入桶头的 O(W²) 常驻控制元数据与载荷容量，或采用按活跃目的地分配的结构。

当前 Router 从初始全量计数阶段开始复用。`Vec::append` 只清空源桶的长度，容量继续保留，因此合并阶段可能长期带着初始化的大桶。初始 owner 邮箱的容量已经释放，Router 是另一份缓冲。应将初始化路由的生命周期与后续轮次路由分开，再对照峰值 RSS；释放逻辑容量不保证分配器立即向操作系统归还内存，也不能据此预报 RSS 降幅。

这项设计不改变最坏情况下的逐轮贪心依赖，也不解决 AA 全局排序。大部分 worker 都参与的高频轮次仍有 A≈W，目录和共享锁可能增加常数；稀疏收益应在单轮基线之间对照。与精确批次版的总用时对比，还混有合并轮次屏障数量的差异，必须分别报告。它先为长尾和高核数提供按实际工作量付费的调度基础，随后才能检验与批次前缀结合的收益。
