# 从动态贪心问题重新设计并行训练

现有 occurrence/snapshot/adaptive 原型没有达到有效利用多核的目标。它们解决了连续文本上一次规则的精确替换，却把初始化、规则选择、位置计划和索引汇总的大量工作留在协调线程。增加 worker 无法消除这些工作；应重新设计任务依赖和状态归属，而非继续把线程数当成主要旋钮。

本报告区分文献已经证明的结论、从当前语义推出的性质，以及尚待实验的方案。它没有把下面的方案写成已经取得的多线程加速。

## 更合适的抽象

语料是若干条带权动态路径，活 token 是节点，邻接边的标签是 `(left_id,right_id)`。同标签边的权重全局求和；每轮选择频次最大、同频字典序最小的标签，再按从左到右选取不重叠出现并收缩，产生一个 fresh ID。

这个问题兼有三种依赖：路径上的局部读写冲突、跨整篇语料的标签聚合、下一轮全局最大值的决策依赖。即使两段文本相隔很远，也可能通过同一种标签影响同一条规则。因而“图是一条路径”不意味着任务依赖图也是局部路径。

按物理位置划分工作不必引入语义分隔符。块可以是存储和调度单位，跨块 token 和邻接边仍存在；需要处理的是边界所有权和更新协议。与此相反，在块边界插入不可跨越的分隔符会改变训练问题。

## 跨领域借鉴什么

| 领域 | 有用机制 | 在这里必须补的条件 |
|---|---|---|
| 确定性并行 MIS / matching | 按优先级依赖图只执行已就绪任务 | BPE 优先级动态变化，还会创建新任务，不能固定初始 DAG |
| 并行层次聚类 | 用局部安全合并条件代替逐次全局选择 | 需证明适用于标签聚合的安全条件，并保留指定规则顺序和词表截断 |
| 并行 Huffman | 利用权重单调性、分层和树高减少贪心轮次 | BPE 有大量既有频率下降，没有同样的双有序队列结构 |
| 增量图系统 / 分布式聚合 | 数据常驻所有者，只交换局部变化和候选摘要 | 热标签不能把所有位置工作集中给一个 owner；严格最大值不能换成近似队列 |
| 确定性数据库 / 有序推测 | 并行准备、依赖检查、提交有效前缀 | 写集不冲突之外，还必须验证全局最高频条件；不能复制整个语料作为每线程快照 |

并行 greedy MIS 的固定优先级依赖、图系统的数据归属和事务提交的具体来源及限制分别见 [贪心算法调研](PARALLEL_RESEARCH_GREEDY.md)、[所有权调研](PARALLEL_RESEARCH_OWNERSHIP.md)、[推测执行调研](PARALLEL_RESEARCH_SPECULATION.md)。

一个值得借鉴的例子是 ParChain：它用互为最近邻的局部条件批量合并，并将内存控制在线性规模。它依赖相应 linkage 的 reducibility，而不是只因为两次合并没有写冲突。这里可以借鉴“先寻找局部安全定理”的方法，不能直接套用算法。[ParChain 论文](https://www.vldb.org/pvldb/vol15/p285-yu.pdf)

同样需要避免错误的困难性外推：平均链接 HAC 的并行困难性和路径上的正面结果针对其特定更新规则，不能证明 BPE 难并行或容易并行。BPE 的全局标签聚合需要单独分析。[ICALP 2024 论文](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ICALP.2024.18)

## 两个有用性质和一个反例

以下是对本项目 fresh ID、加权重叠频次语义的推导。

1. **旧标签频次只降。** 每个新建邻接都包含本轮 fresh ID，因此不会增加两个旧 ID 组成的标签。旧频率可作为惰性优先队列的上界。
2. **新标签频次不超过本轮 winner。** 每一类新边可注入本轮被替换的 token 或它们之间的边界，频次不超过加权替换数；替换数又不超过被选 pair 的加权重叠频次。所以每轮最高频次非增。

第二条仍不足以把前几个旧候选一起选中。设 `a<b<c<d<e`，输入包括权重 3 的 `abc` 与权重 2 的 `de`。最初 `ab=bc=3`、`de=2`。先选 `ab→X` 后，`Xc=3`，第二条应是 `Xc`，不能提前选 `de`。`ab` 与 `de` 连 token 类型都不共享，仍不构成精确贪心的前两条规则。

BatchBPE 提供了按 token 端点排除冲突的批处理启发，但其跳过冲突者继续搜索、词表容量启发式及 self-pair 处理不能直接当成本项目的逐规则等价证明；论文也讨论了规则顺序和词表可能改变的情形。[BatchBPE，第 3 节](https://arxiv.org/html/2408.04653v1)

## 候选一：有证明条件的连续候选前缀

可以先验证一个保守、无需回滚的批次规则：

1. 在稳定状态中，按精确 `(频率降序, pair 字典序升序)` 读取当前候选。
2. 只取连续前缀。若新候选 `(a,b)` 满足 `a` 曾作为已选 pair 的右端，或 `b` 曾作为已选 pair 的左端，立即停止；不跳过它去选更低频的 pair。
3. self-pair `AA` 单独执行。若前缀已经非空，则在 `AA` 之前停止。
4. fresh ID 按原候选顺序分配；词表剩余规则数仍是硬上限。

证明思路：这些非 self pattern 的出现不会重叠，所以被选 pair 的频率不受先前批内规则影响。若 `Ai Bi→Zi`，中间或最终新边有三类，其旧边祖先为：

| 新边 | 批前旧边祖先 |
|---|---|
| `(L,Zi)`，L 未被收缩 | `(L,Ai)` |
| `(Zi,R)`，R 未被收缩 | `(Bi,R)` |
| `(Zi,Zj)`，包括 i=j | `(Bi,Aj)` |

同一新标签的出现可单射映射到同一种旧边，piece 权重保留，因此新频次不超过祖先旧频次。每种祖先都与某个已选 pattern 冲突，不能出现在所取前缀内：若祖先更早，之后选 generator 时就应停；若祖先更晚，遇到它就应停。所以祖先排在整个前缀后。fresh ID 大于所有旧 ID，还使新边字典序严格晚于其祖先，覆盖同频情况。

这是一个可检验的精确批次充分条件，不是最大批次算法，也不是新的通用并行复杂度定理。它与 BatchBPE 的保守早停思路、YTTM 对未完成规则保留旧频率上界的做法相关。需要用独立 recount oracle 核对完整规则和最终序列，再测真实输入的安全批宽。[YTTM 固定源码及推导](PARALLEL_RESEARCH_IMPLEMENTATIONS.md)

若从惰性堆读取，还必须保持未完成规则相关旧标签的上界，不能过早刷新、下调或删掉用于限制新标签的证据。证明批次顺序合法，也不自动证明共享数组并发写合法：相邻 `ABCD` 上同时替换 `AB/CD` 时，边界计数必须得到最终 `Zi/Zj`，而非分别使用过时邻居。

原生探针已接入并保持串行应用。英文/中文 4 MiB 连续语料的 3,000 条规则分别形成 251/275 批，平均 11.95/10.91 条；全部 20 个 fixture 的 checked/unchecked 批次计数相同，输出与直接串行参照相同。448 次独立完整轨迹对照也通过。长链和 self-pair run 仍基本为单步。[诊断明细](ablation_results/certificate-summary.md)

这支持继续验证批量应用，不表示已实现相应速度倍数。一个具体机会是直接生成批次结束时的邻接和位置索引：在 `ABCD` 上批量选 `AB/CD`，最终只需要 `Zi/Zj`，可以省去逐条实现里曾产生又失效的 `Zi/C` 记录。由于批次 heads 与 tails 不相交，每个匹配可从稳定旧上下文识别左右邻居是否也将被收缩；相邻匹配的共用边由左匹配处理一次。需要一轮稳定读取和不相交写入协议，同时将 delta 留在对应所有者，避免协调线程再次遍历所有位置。[批次最终邻接方案与限制](PARALLEL_RESEARCH_OWNERSHIP.md)

这些实现计数允许变化，固定语义要求的是完整规则 key/count/ID 顺序与最终序列相同。新的批次算法不必保留旧算法的每一条 stale occurrence。

独立 Rust 参照已经验证了整批最终计数：在穷举三字符字母表的短串和 2,000 组加权随机输入上，每批的增减量都与替换后的完整重算一致，并单独覆盖相邻同规则和不同规则匹配。这个参照为便于核验分配了临时标记数组；它尚不是经过内存优化的并行内核。原生探针与独立参照的检查及哈希见 [验证记录](ablation_results/certificate-checks.json)。

## 候选二：把状态留在数据附近

需要比较两种不同的归属，而不是先认定哈希分片最好。

**按文本块持有位置和局部计数。** occurrence 由其左端原始位置决定 owner，旧频率留在 owner，协调层只验证可能胜出的候选并归并新 key 摘要。块边界保持可跨越；长 token 可跨多个块。一次规则的稳定上下文、AA run 前缀奇偶、跨块边变化按明确协议处理。大多数位置更新本地完成，适合 NUMA 和后续磁盘块，但同一 key 的局部表会重复，负载也可能倾斜。

**按 pair 持有全局频率和候选队列。** 每个 owner 维护其完整计数和局部最大值，最后只归约少量候选。语料处理者向目标 owner 分组投递 delta。热点 pair 的长位置列表必须分块并行处理，不能由一个 owner 串行扫描/复制。跨 owner 的数据交换可能接近每次替换一次，必须实际量通信字节与内存高水位。

二者可以组成两级结构：物理块保存位置片段，pair owner 只保存标量与片段目录。但每个 fragment 的元数据、缓存行迁移和生命周期都要计入总空间，不能只报告 corpus 的 4N 或 2N。

## 候选三：有界推测，以及先减少总工作

若保守前缀太短，可让 worker 只读计算更宽候选窗口的 occurrence、上下文和 delta，认证后提交最长有效前缀。缓冲限制为被访问 occurrence 的日志；不复制全语料，不允许未认证写入逃逸。需要统计失败原因、丢弃工作、日志峰值和认证时间。若串行认证仍逐位置处理，换成事务术语也不会解决瓶颈。

RLE、重复片段共享与 RLZ 上的精确替换是另一条轴：它们可能直接减少 work，比把相同工作分给更多核更有效。但词级去重、run 计分和 tie 语义必须逐项适配；不同 grammar 构造不能冒充相同 BPE 训练。[压缩领域调研](PARALLEL_RESEARCH_PAPERS.md)

## 下一轮实验的判据

先记录安全批宽、有效 occurrence、实际变化 key 数、owner 热点与边界流量，再决定实现顺序。对于足够大的任务，四核 3× 是值得检验的目标；理想 Amdahl 模型已要求串行份额不超过 1/9，实际还需容纳同步和负载不均衡。

性能验收同时看同实现 1→2/4/更多 worker 的强扩展、对最佳直接串行的绝对耗时、CPU 时间/墙钟、峰值内存和初始化。不能用更慢的 1-worker 包装器抬高加速比。对长链、AA、同频密集和长尾轮次，允许报告失败边界；不承诺任意输入都达到同一个倍数。

外存实现还需控制驻留块、索引和日志，测实际读写字节；mmap 并不自动满足内存预算。本轮先保留精确语义和可解释的工作量，避免以复制索引或全语料重扫隐藏并行成本。
