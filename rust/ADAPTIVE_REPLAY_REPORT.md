# 精确切区与出生位置重放：本轮收敛结果

后续已完成[16 MiB、32,000 合并的核心方案复核](batch_results/radical-full-v1/README.md)。同一补测窗口 n=2 中，W4 inline/chain 英文为 3.627/2.908 秒、中文为 1.987/1.594 秒，inline 两者均慢约 25%。因此下面的小测是历史筛选记录，不能据此将内联重放视为通用最优；大规模复核也没有确认整进程内存一致下降。

本轮推进了三个 Rust 原型：按本批 posting 工作量选择切点、重放出生位置以删除 BirthNode，以及重放计数的内联存储。**没有取得通用的四线程 3× 加速，也没有证明训练总内存一致下降。**计数内联改善了重放的实际成本，重复串上的重放收益在两个小测窗口都出现；这些结果支持保留条件性候选，尚不足以替换当前速度基线。

所有路径保持串行 greedy BPE 的规则顺序、weighted frequency 和最终 token 完全相同，不需要空格预分词。本轮没有实现外存训练，也没有验证双路或几十核机器。后续工作由主 agent 完成，没有恢复或新增 subagent。

## 1. 工作量驱动的切区

[实现](experiments/radical/owned_adaptive_cuts/DESIGN.md)在每批开始时，用最长 posting 的分位或各 posting 的分层样本生成候选物理切点。随后对固定切点和候选切点计算真实历史访问范围，只接受最大区域访问数更小的候选。同分保留固定切点；AA 回到固定切点，W1 跳过采样。T≤W，不用更多小任务掩盖倾斜。

有序 posting 允许候选构造仅读取 O(BT) 个样本、排序 O(BT log(BT))、范围查询 O(BT log Hmax)，不复制全位置索引。符合适用条件的采样候选，单区历史访问上界为 `<1.5H/T+B`；不适用于预算回退或有效改写的 CPU 时间。额外候选元数据有 8 MiB 选择守卫；它不是整次训练的硬内存预算，部分实际容量检查发生在分配后。

两模式共同使用预计算 B×T 范围矩阵。少做重复二分是共同改动，不能把它归因于 adaptive 开关。实现的样本是 `(u32,usize)`，本机大小 16 B，设计稿原先的 8 B 估算不适用于此实现。

256 KiB、512 规则、W4，非 AA 批次中“每批最大历史访问数的累计和”如下。计数两轮相同。

| 输入 | 固定切点 | 自适应 | 降幅 | 启用批数 |
|---|---:|---:|---:|---:|
| EN 连续文本 | 54,935 | 53,698 | 2.25% | 33/68 |
| ZH 连续文本 | 10,708 | 7,725 | 27.86% | 70/76 |

它改善的是扫描负载。stale 项仍要读，有效项还要写端点和做哈希；因此访问均衡不能直接换算训练加速。样本容量峰值 EN/ZH 为 5,632/6,656 B，范围矩阵峰值从 1,440/1,696 B 变为 2,880/3,392 B，路由头仍有 O(TW) 成本。

## 2. 不存出生链，直接重放填最终位置表

[实现](experiments/radical/owned_replay_birth/DESIGN.md)的第一遍只路由新边的权重和出现数。全部合并写入完成后，保留的新 key 按准确计数分配最终 posting，分成互不重叠的区域切片，第二遍由区域任务直接填入。每个实际匹配必须满足 raw `corpus[p] == HEAD|fresh_id`，裸尾 ID 不可冒充 head。fresh/fresh 邻边由左匹配的右出生唯一生成。

这改变了并行填充的单位：一个很热的新 key 的最终数组也可以由多个区域线程写各自的段，原链方案由一个 owner 遍历和填完。代价是再次扫描 selected 历史 posting、预零最终数组、计数与写入目录，以及更晚释放 selected 数组。每个历史 key 只选择一次，额外累计位置访问 O(N)；这不是整个训练算法的线性时间声明，范围查询、选择、哈希和同步仍存在。

重放路径的实际 BirthNode 数与出生节点容量均为零。EN/ZH 的历史位置访问分别从 202,877/29,670 翻倍至 405,754/59,340。语义出生边数和最终存入的出生位置数与控制一致。两个指标必须区分：累计 `generated_birth_records×8` 不是省下的峰值内存。

不需要寻找一条“永远不会跨越”的文本边界。切点可以穿过长 token，按出生位置的目标区域记数；至多 T−1 条跨区左出生例外保留小描述符，在目标段预留末槽，区域任务 join 后填写。其余任务拥有安全 `split_at_mut` 切出的独占切片。第一遍端点仍使用已验证的 tagged 协议；本轮没有新增 unsafe。长度表为 u32，超过 255 的 token 不需要每语料位置额外扩宽。

## 3. 根据首轮证据追加：内联区域计数

第一轮自然语料的重放较慢，元数据与填充成为明确成本。[追加实现](experiments/radical/owned_replay_counts/DESIGN.md)提供同二进制 `chain / replay / replay-inline`：一到两个区域计数不分配小 Vec，第三个区域才转堆数组。region/count 各为完整 u32；转换检查、顺序、边界和填充协议保持原样。

容器头从 24 B 增至 32 B。三段及以上的堆记录从 16 B/段降到 8 B/段，一到两段则完全省掉计数数组分配。该变化也会增宽旧 key 的空 CombinedDelta，因此必须核算总成本。泛型分别实例化原 Vec 和 inline 控制，没有给 Vec 控制加 enum 包装。

W4 的达阈值出生 pair 中，EN 的一/二/多段数量为 2,999/6,643/9,616，ZH 为 1,583/2,043/1,712；一到两段占 50.07%/67.93%。统计的是累计创建的 fresh pair，每个 pair 只在创建批次出生，不是最终词表大小。

| W4 元数据指标 | EN Vec→inline | ZH Vec→inline |
|---|---:|---:|
| staging 计数 heap 容量峰值 | 51,840→18,176 B | 20,096→3,552 B |
| staging 头及计数容量峰值 | 109,184→83,712 B | 48,768→35,872 B |
| 同批临时容量代理峰值 | 534,336→508,352 B | 347,312→324,240 B |

上述代理按实际泛型类型重算，包含 selected、计数/暂存、最终 posting、路由或填充描述符等载荷；HashMap 公共 capacity×元素大小不包含真实桶、控制字节或 allocator。代理峰值不是 RSS，各项峰值不能随意相加。AB 的同时存活代理反而略增 48 B，说明内联并非每种形状都省空间。

## 同窗口小测

机器只提供六个可见 CPU。W1 限 CPU 5；W4 限 CPU 0/1/2/5。aHash、lazy heap、global posting、tagged-fused、region、T=W；直接串行为 CF32/aHash/checked。自然语料为 256 KiB、512 规则，AB 为 64 KiB。报告完整训练调用壁钟，包含初始化、线程池与收尾，不包含读取 JSON 和写 trace。VmHWM 在训练后、trace 前读取，但包含输入准备及进程此前的高水位。

第一窗口随机交错 40 次调用，各格 n=2；第二窗口仅对计数方案追加 26 次，各格 n=2，第二轮反转第一轮次序。第二窗口的三种出生模式来自同一个新二进制。两个窗口不能混拼速度比。

第一窗口中位耗时，单位 ms：

| 模式 | EN W1 / W4 | ZH W1 / W4 | 自身 W1→W4 EN / ZH |
|---|---:|---:|---:|
| 固定切点 | 61.72 / 56.28 | 29.54 / 26.93 | 1.10× / 1.10× |
| 自适应切点 | 61.98 / 42.05 | 28.72 / 27.12 | 1.47× / 1.06× |
| 出生链控制 | 73.30 / 45.55 | 30.93 / 18.54 | 1.61× / 1.67× |
| 原重放 | 71.49 / 56.31 | 33.43 / 28.11 | 1.27× / 1.19× |
| 直接串行 | 44.57 | 21.60 | — |

固定/自适应切点同一二进制，出生链/原重放另一个二进制；跨这两组不隔离单个改动。EN 自适应耗时改善明显，但扫描最大值只降 2.25%，初始化与规划时间也有较大波动；不能把全部 25.3% 耗时下降解释成切点收益。ZH 的扫描均衡改善未转换成整次净收益。原重放在自然语料 W4 慢约 23.6%/51.6%，AB 则 12.24→9.17 ms，快约 25.0%。

第二窗口中位耗时，单位 ms：

| 模式 | EN W4 | ZH W4 | AB W4 |
|---|---:|---:|---:|
| 出生链 | 51.56 | 26.32 | 11.09 |
| 原重放 | 66.58 | 30.58 | 7.83 |
| 计数内联重放 | 50.78 | 21.28 | 7.52 |
| 直接串行 W1 | 37.78 | 23.75 | 未测 |

inline 相对 Vec 的中位耗时下降 EN/ZH 约 23.7%/30.4%，但 EN Vec 两次为 84.59/48.56 ms，不能用均值中心证明稳定幅度。inline 对出生链 EN 基本持平且范围交叠；ZH 19.97–22.60 ms 低于 chain 26.10–26.54 ms；AB 7.06–7.99 ms 低于 chain 10.41–11.76 ms。n=2 只作候选筛选，不是统计显著性证明。

inline 自身 W1 为 EN/ZH 61.05/32.10 ms，W1→W4 **1.20×/1.51×**；同窗直接串行/W4 为 **0.74×/1.12×**。不能靠 AB 的局部收益或更慢的单核分母宣称多核目标达成。W4 CPU/wall 约 EN 2.70、ZH 3.23 核，说明线程有工作，但总 CPU 成本增长限制了加速。

inline 相比 Vec 的训练 VmHWM，EN 9.39→9.34 MiB，ZH 8.36→8.39 MiB，AB 4.57→4.54 MiB。计数数组的确定性节省成立，整进程内存没有一致下降；目前不能声称该路线已找到通用速度/内存甜点。

## 验证、复现与决策

- 三个 crate 的 Rust lib 测试分别 28/27/30 项全部通过；继承测试有重复，不合计为不同的独立测试。最终源码 fmt、strict Clippy、release 均通过。
- 独立 naive 完整规则及最终 token 门控分别 94/96/96 次，共 286 次，覆盖 weighted/u64、AA、fresh/fresh、低频过滤、长度 512、跨切点、W>N、HEAD 域回退。66 次计时也核对完整轨迹。
- [40 调用归档](batch_results/radical-adaptive-replay-v1/README.md)、[26 调用归档](batch_results/radical-replay-counts-v1/README.md)保留原始各轮耗时、CPU、HWM、指标、实际 CLI、输入/二进制/源码哈希、源码 capsule 与共享基座证明。计数文档有一处测后语义描述修正，实测 capsule 原样保留，Rust/Cargo 字节未变。
- 共享 Rust 基座仍为 `c1d8fc3bf4fb31bfa59afd545b37a7697c15ec1f`，26 个共享文件逐字核对未变；没有修改另一个 tokenizer benchmark。

收敛决策：不再盲扫微区数，不默认切换 adaptive 或原 replay。保留有序 posting 及精确区域填充协议；replay-inline 作为重放的优先实现候选，尚不替换现有通用速度基线。AB 的收益提示“热点位置多、出生 key 少”更适合直接分段填充；这还不是已实现、已验证的自动选择策略，不能直接按语料名字分支。

若继续主线，优先减少每批 O(D) 写入目录组织及多轮同步，并在同一个方案中保留快速串行路径；其次才是最终 posting 的未初始化填充。此次预零字节 EN 约 1.08 MB、ZH 约 0.16 MB，不能仅凭存在一次额外写就认定它是主瓶颈。外存方向可利用不可变有序 posting，但频率/heap 常驻、构建双峰、磁盘读放大还未解决。
