# Independent review of the birth-neighbor certificate

I tried to construct a current overlap that the newer key's immutable 64-bit birth mask would miss. Under the draft's stated lifecycle—every new edge contains the current batch's fresh ID, all masks for that batch read the **post-apply final corpus**, and no key gains positions after its birth epoch—I found no such counterexample. The certificate is a one-sided negative test: a missing bit proves disjoint current occurrences; a present bit says nothing because of collisions or dead old neighbors. It must never skip a positive or unavailable candidate in the greedy prefix.

The closest attacks clarify required invariants:

- In `Y X A B`, merging `AB→Z` makes the new `(X,Z)` overlap the surviving old `(Y,X)` at `X`. Querying the old key's mask is unsound; the new key's birth mask must record `(Y,X)`. This remains true if the old key and new key reside in different owners.
- An attempted later creation of adjacency between two *unchanged* old edges fails. Start with `(U,A)` and `(B,V)` separated by a token `M`. Removing `M` requires merging `(A,M)` or `(M,B)`, which destroys one old edge and creates an edge containing that merge's fresh ID. More generally, two surviving pair occurrences retain their shared token identity; they cannot become adjacent for the first time after both births without changing an endpoint. This is the step needed for an immutable birth mask, rather than an assumption that all neighbors are timeless.
- Two keys born in the same batch have no true within-batch time order even when `max(endpoint_id)` differs. For adjacent disjoint matches `AB→Zi` and `CD→Zj` in `L A B C D R`, the post-batch edges include `(L,Zi)`, `(Zi,Zj)` and `(Zj,R)`. Either same-batch key's mask must see its final adjacent key. Constructing masks from pre-apply neighbors, from only one producer chain, or before every owner has completed the endpoint apply can miss this relation.
- Initial IDs encode token identity, not birth time. All initial pair keys are coeval. Choosing one by the larger `max(endpoint_id)` remains sound only because *both* initial masks scan the same initial corpus. A test should use adjacent initial keys with unequal ages and another with equal ages.
- Long tokens make physical `pos±1` an invalid right-neighbor rule. The birth scan must use the linked token boundary `right=pos+lengths[left]`, `after=right+lengths[right]`; the left neighbor's ID comes directly from the preceding token's end tag at `pos-1`. A zero sentinel means a piece boundary, not a neighboring pair. Post-apply end tags must already be written before any birth scan.
- Weighted frequencies do not change whether pair edges share a token. They do matter to the fresh-pair priority bound: each occurrence of a fixed new key must map injectively, with the same piece weight, to one old boundary edge. The existing adjacent-selected-match suppression is necessary so a fresh/fresh edge is not counted twice. The older ancestor's equal-frequency key ranks before the fresh key because a fresh ID increases the changed endpoint. A complete weighted trace test is necessary; a mask test alone does not establish greedy priority.
- A key filtered below `min_frequency` cannot later regain frequency: after its one birth epoch, all later edges contain newer IDs, so that fixed key only loses occurrences. Its bit may still appear in a neighbor's mask without an Entry; that is conservative. The mask of an eligible key must aggregate every birth occurrence **after** the full weighted frequency decision, including producer chains from all owners.

`age(key)=max(left_id,right_id)` orders birth epochs because fresh IDs increase and a newly formed edge contains that epoch's ID. Within one epoch the order is arbitrary but both masks must be built from the same complete final corpus. For any current adjacent occurrences of `P` and `Q`, let `Q` be the later-born key. The surviving `P` occurrence already existed when `Q` appeared, and their adjacency cannot first arise later while both occurrences survive. Thus `Q`'s birth scan recorded `P`'s bit. This proves the negative direction only if every key's entire position set is born once; stale posting entries are harmless false positives.

Required focused tests before using the certificate:

1. Separate pieces containing `AB` and `BC` with a deterministic priority order: type conflict, mask negative, both admitted in one batch, full rule/frequency/final trace unchanged. In `[A,B,C]` and `[C,A,B]`, test the two actual overlap orientations and require a positive stop. Cross-piece sentinels must not create a neighbor.
2. Force `AB→Z` next to old `(Y,X)` as above, then compare their masks; force two disjoint same-batch rules next to each other and assert that the final fresh/fresh key and both adjacent fresh keys record each other. Check both keys' owner routes have finished before selection resumes.
3. Use an initial adjacent pair with unequal numerical ages, an equal-age pair, and a newly born key containing an older fresh ID. This checks the max-ID choice and coeval cases independently of any rule count.
4. Build tokens of length 2, 4 and over 255, with neighbors on both sides and piece boundaries. Traverse logical token starts after apply to recompute exact neighboring pair keys and verify that every current adjacency has the required bit in the chosen key's mask.
5. Run nonuniform piece weights, `min_frequency` filtering and a forced 64-bit bit collision. A collision may only stop a batch; a filtered key must not be queried as a candidate. Keep AA singleton even if its bit test would be negative.
6. Use `ABABABCD`: initial `AB` outranks `BA`, but its fresh `ZZ` can outrank `CD`. A positive `AB`/`BA` relation must stop the prefix at `BA`; the implementation must not skip to `CD`. Assert the complete greedy rule/frequency order.

A useful broader debug oracle is an independent logical-corpus traversal after each tiny weighted epoch: for every pair of adjacent **currently eligible** key occurrences, choose the larger-age key and assert its mask contains the other's bit. This directly probes false negatives, including same-batch births and stale historical positions. Full reference traces remain necessary to check the separate fresh-priority argument. I have not reviewed the in-progress implementation or run Cargo; this is a design-level counterexample audit.
