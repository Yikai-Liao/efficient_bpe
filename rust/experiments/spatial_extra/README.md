# Extension-only spatial probe

`spatial_extra.patch` records the addition of `parallel_pair_owned_spatial_extra` to the existing `parallel_spatial.rs` engine through a compile-time `EXTRA_ONLY` choice. It does not duplicate the native implementation. The current `parallel_pair_owned_spatial` remains the same full-window, right-neighbor probe. The patch is already applied to native sources; this file preserves its derivation.

The hashes in `base-hashes.json` identify the exact source before application. `git apply --check rust/experiments/spatial_extra/spatial_extra.patch` passed against those frozen files. Targeted tests, strict Clippy, release build and 80/80 complete oracle traces subsequently passed; the [fixed-budget screen](../../batch_results/pair-owned-spatial-extra-v1/README.md) archives those checks and timings.

## Why the cutoff is unchanged

Let `[0,k0)` be the token-type certified base and `[k0,k)` the budgeted extension. The base has no overlapping pair occurrences. Every conflict in the window therefore touches an extension occurrence. For each valid extension `AB` at `pos`, the new probe checks the pair `(X,A)` immediately to its left, using the right-end token marker at `pos-1`, and `(B,C)` immediately to its right, using the token at `after`. If either neighbor key is in the candidate window, it reports `max(rank(AB), rank(neighbor))`. Each overlapping pair has exactly this adjacency at one of the extension occurrence's sides; the minimum conflict cutoff is thus identical to the old full-window, right-only probe. A zero sentinel stops the check at a piece boundary. The base version still scans all keys and checks only right neighbors through the same const-generic function.

The candidate order, 256 cap, 64 speculative tail, global `2H0` length budget, metadata phase, AA handling, selected-prefix truncation, and owner candidate return are unchanged. The extra variant's `probe_visits` invariant now compares the worker count to `sum(histories[k0..k])`, since base lists are no longer read. The original variant retains `sum(histories[..k])`. Complete rule/frequency/final parity is expected; the new directed unit tests cover an extension whose conflicting base occurrence is to its left, one to its right, and an `AB`/`BC` pair separated by a sentinel.

For the archived 256 KiB quick, every metadata phase proceeded to a probe. The history counters predicted visits falling from 515,737 to **327,003** on English and from 54,249 to **32,087** on Chinese, with exactly the same 55/81 epochs and width sums 512/512. The fixed-budget screen confirmed all these counts. It did not show a four-worker call-time improvement in the single sample: EN spatial v1/extra were 0.10043/0.10820 s and ZH 0.04390/0.05369 s. The extra left lookup and unchanged extra stages remain costs; fewer record visits alone do not establish a speedup.
