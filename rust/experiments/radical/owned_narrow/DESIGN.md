# Whole-call narrow atomic corpus

`owned_narrow` isolates corpus endpoint width from the frozen `owned_grouped_inline` trainer. The owner index, inline posting lists, exact candidate order, AA parity, route accounting and grouped birth fill are unchanged. `--corpus-width u32|u16|auto` defaults to `u32`, which is the same-binary control. The `u16` choice is strict; `auto` chooses `u16` only when the full-call bound below holds and otherwise uses `u32`. One dispatch at the training entry calls a separate monomorphized kernel; there is no width tag or branch at each endpoint access. Token lengths and posting positions remain `u32`.

Let `L = initial_lengths.len()` and `R = max_merges`. Shared input validation requires dense, used initial IDs in `0..L`, and every merge appends exactly one new ID, beginning at `L`. Thus the largest ID that this call can store is at most `L + R - 1`. A checked `L + R <= 65536` proves all initial and fresh IDs fit `u16`; it also handles `R=0` and rejects arithmetic overflow. The strict mode rejects a failed bound before constructing the worker pool or index, after shared input validation. Automatic mode falls back for the entire call. The only corpus stores are `write_merge`'s zero and new ID; initial conversion copies validated IDs. Both use a debug assertion followed by a safe narrowing cast, so release hot paths do not repeat the proven bounds check. Reads widen to `u32` before all existing indexing and pair-key calculations. This limit applies to **IDs**, not token lengths: `initial_lengths` and merged lengths stay `u32` and a 513-position token is covered by a targeted test.

The narrow branch explicitly allocates a new `Vec<AtomicU16>` of input length and fills it while the original `Vec<u32>` is alive, then drops that input. It does not reinterpret the original Vec pointer as a differently aligned allocation. `endpoint_corpus_capacity` reports the actual resulting capacity; `endpoint_corpus_bytes` is that capacity times element size. `input_corpus_capacity` is the original `u32` capacity, and `conversion_simultaneous_capacity_bytes` is the capacity-based upper bound `4*input_capacity + width_bytes*endpoint_capacity` for the two corpus buffers alone. Allocator bookkeeping, temporary allocator retention and all other trainer data are excluded. In the narrow case, the two buffers really coexist during conversion, so the approximate 6N transient can offset the later 2N steady-state corpus payload. The wide control retains the inherited consuming `Vec<u32> -> Vec<AtomicU32>` conversion; its reported two-capacity sum is only a conservative payload bound because allocation reuse is possible. Training VmHWM and process CPU are sampled with the same CLI timing boundaries as the other radical experiments.

The access barrier remains unchanged: planning reads a stable pre-apply corpus; disjoint writes complete before the next candidate search or post-apply verification. Relaxed atomics still prevent data races at shared endpoint boundaries, while Rayon phase joins provide ordering between phases. Near-limit tests cover `L+R` equal to 65535, 65536 and 65537, a real fresh ID of 65535 in `u16`, a real ID of 65536 via `auto` fallback, and strict rejection at that boundary. The existing weighted, adjacent and AA differential cases run through all three width modes.
