# Combining direct old-key decrements with owner-local commit

This integration retains the two independent switches from `owned_fused` and `owned_direct`: `--commit-mode separate|owner-fused|overlap` and `--reduce-mode combined|direct-old`. Defaults remain `separate` and `combined`, providing a same-binary control. The candidate for screening is `owner-fused` plus `direct-old`; overlap remains a correctness-tested experimental switch, not an assumed improvement.

Planning completes against a stable corpus. All old keys only lose frequency; each unique owner directly applies producer decrements, removes keys below threshold, and aggregates only fresh-key counts when `direct-old` is selected. Lazy heaps defer old-key refresh; eager heaps publish each surviving touched key once after its final decrement. Fresh postings are allocated only after the full frequency crosses the minimum. See the proof and cache-locality tradeoff in [the independent direct-decrement design](../owned_direct/DESIGN.md).

With `owner-fused`, an owner begins filling its fresh postings immediately after its own reduction. No other owner can modify those keys, and all producer routes are already immutable, so the global barrier between owner reduction and fill is unnecessary. The corpus apply stage still joins first. The optional `overlap` schedule also overlaps apply with the fused owner branch; owner code never reads corpus, and debug birth-key validation waits until both branches join. See [the independent schedule design](../owned_fused/DESIGN.md).

The integration preserves final-key grouped birth chains, inline posting ownership, exact batch selection, AA parity, and the W-producer/W-owner layout. It adds no corpus/index copy. Full cross-product tests cover both reducers, all three schedules, both heap policies, W1/W2/W4, several chunk sizes, weighted inputs, ties, adjacency and long runs. Independent full-trace oracle checks must follow compilation.

Timing and memory definitions match the independent prototypes. `update_stage_seconds` is outer wall time including route metrics and, in debug builds only, post-join key verification. Branch timers can overlap and must not be added to it. Per-owner temporary capacities are summed as an upper bound per batch, then maximized across batches; fused owners need not hold all maps at once. This sum is not a simultaneous-allocation measurement. The full checked training call, final statistics and destructors stay inside `call_seconds` and `call_cpu_seconds`.
