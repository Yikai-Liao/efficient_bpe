# 出生位置重放填充

状态：独立原型；27 项 Rust lib 测试、最终源码 fmt/strict Clippy、release、80 次标准和 16 次定向独立完整轨迹对照已通过。性能仅在限定同窗口 screen 中评价。此 crate 从冻结的 `owned_ordered_posting` 克隆。`--birth-fill chain|replay` 默认 `chain`。`replay` 只接受 `--posting-order global --endpoint-plan tagged-fused --region-mode region`；固定 `T=min(W×regions_per_worker,N)` 个 region 和 W 个唯一 pair owner 保持不变。tagged ID 超出 31 位域时，整次训练沿已有 `two-pass/dynamic` 路径回退，`birth_fill_effective=chain`。`chain` 是同一二进制内保留的原 8 字节 BirthNode 控制路径。

第一遍 region 规划仍使用稳定的批前邻居、精确的类型冲突证书和原有 AA 全局 LTR parity。每条旧邻边向目标 owner 路由负向权重与出现次数；每条本批新边仅向目标 owner 路由正向权重与出现次数，不分配 BirthNode。跨区左出生仍在规划时按目标 region 注入频次，另外保留至多 `T−1` 个 `CrossBirth` 描述符供第二遍填位。所有端点写入完成后，owner 合并各 region 的 Delta：旧 key 只减；本批 fresh key 只增。频率达阈值的新 key 放进本批 staging，按准确出现次数建立已经初始化为零的 `SmallPosting`，并保存每个有记录的 `(region,count)`。低频 key 不分配最终 posting。这里仅遍历本批路由和新 key，不逐批扫描持久 owner 索引。

随后按每条新 posting 的 region 计数，把它的可变切片用安全的 `split_at_mut` 分开；不同 key 的切片来自不同 `SmallPosting`，同 key 的 region 切片也互不相交。每个 region 的写描述符拥有自己的切片，Rayon 任务独占它。对于跨区左出生，其已计入目标 region 的末槽留给 join 后写入；剩余本地切片由该 region 任务填充。填充完成、描述符与所有切片借用结束后，才把 staging 中的新 Entry 移入 owner 并发布 heap 候选。不需要新增 unsafe，也不需要按出生位置建立另一份 `Vec<u32>`。

第二遍再次访问本批所选 key 的历史 posting。全局有序性允许每个 region 用 `partition_point` 取得区间；一条历史位置 p 只有在最终 `corpus[p] == HEAD | rule.new_id` 时才是本批实际合并起点。fresh ID 本批唯一，且同一个 pair 的 posting 只在初始或出生时生成、以后不追加，所以 stale 位置不会冒充这条规则的新 head。此时右邻是 `p+len[new_id]` 的最终 live head，产生 `(new_id,R)`；左侧若 `p−1` 是旧 ID 的 tail，就由旧长度恢复其 head，产生 `(L,new_id)`。若左邻已被本批另一次合并替换，tail 是本批 fresh ID，左出生被抑制；相邻 fresh/fresh 边由左侧匹配的右出生唯一生成。AA 的已选匹配使用同一规则；未选的重叠 AA 位置没有本批 fresh head。跨区左出生在源 region 的第二遍跳过，由之前的描述符填入目标末槽。按规则及 posting 位置扫描时，一个 fresh key 的本地出生位置递增，按 region 拼接后保持全局有序，因此不需要链反转或比较排序。

重放使每个被选择的历史 posting 多扫描一次。每个 key 只被选择一次，故累计额外位置访问不超过初始合格 posting 与已存出生 posting 的总数；固定 region 的边界查询另有每批 `O(T×batch_width×log H)` 成本。新临时空间是本批 Delta、每新 key 的 staging 头和 `region_counts` 小 Vec、`O(D)` 写描述符以及 `O(T)` 跨区例外，其中 D 是本批非空 `(region,key)` 段数。`region_counts` 的 Vec 头与 capacity 可能在每 key 位置数很少时超过省掉的 BirthNode 字节；本版保留这一成本以验证正确性和并行填充效果。预零会多写每个保留位置一次。保留 selected posting 直到填充 join，也延长了它与新 Entry 的同时存活期。

指标中的 `generated_birth_records` 始终表示语义上产生的新边数，应与 `chain` 相同；`replay_birth_nodes_actual`、`grouped_birth_nodes` 与 region 出生节点容量在重放路径应为零。`replay_posting_visits` 是第二遍物理访问总数，`replay_filled_positions` 是通过阈值的新 posting 实际填入数，`replay_zero_initialized_bytes` 是累计预零的 payload 字节。`replay_peak_selected_heap_capacity_bytes` 只计 selected posting 的 heap 槽；`replay_peak_staging_header_capacity_bytes` 含 staging Vec capacity 及逐 key `region_counts` Vec capacity；`replay_peak_initialized_posting_capacity_bytes` 和 `replay_peak_descriptor_capacity_scaled_bytes` 分别计新 posting heap 槽与 descriptor 的 capacity×类型大小。`replay_peak_simultaneous_capacity_proxy_bytes` 取同批 reduction/fill 两相位暂存 capacity 代理的较大值，包含 selected、路由或 descriptor、staging 及新 posting，但不含持久 owner map、allocator 桶布局和 rehash 双峰；它不是 RSS。`replay_fill_seconds` 包含切段、第二遍扫描、跨区末槽写入和发布新 Entry，不能只解释成内存拷贝时间。

完整规则轨迹 `(pair,frequency,order)` 和 final tokens 必须与串行参考一致。局部测试覆盖不等权重、AA、同批 fresh/fresh、长 token 跨多 cut、多 piece、W>N、低阈值及 tagged 域回退；统一门控再检查随机完整轨迹、strict Clippy、release 和相同配额的两模式计时。性能结论必须同时看 BirthNode 节省、描述符及保留 selected 的峰值、第二遍访问和整个调用时间。
