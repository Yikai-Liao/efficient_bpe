# Integer-key hasher controlled experiment

This independent crate copies frozen `owned_grouped_inline` and changes only the map/set builder. `--integer-hash std|ahash` defaults to `std`, the same-binary control. At the timed training entry, one match calls a monomorphized `train_impl<H>` with either `std::collections::hash_map::RandomState` or cached `ahash 0.8.12` `RandomState`. `Owner.entries`, producer `Route.delta`, the owner's combined delta, selected pair map/set and candidate head/tail sets all use that builder. The physical `owner_for(pair, workers)` mapping, rule selection, AA parity, grouped birth chains, unique posting storage and update barriers stay unchanged. A typed kernel avoids a per-lookup enum branch.

This compares the aggregate hashing cost of integer-key operations rather than a proposed semantic change. Builders can choose different seeds and hash-table iteration orders. The global heap still ranks candidates by checked frequency and pair key; delta addition is checked integer addition, while birth position order need not be sorted for non-AA and AA sorts its selected posting before parity. These properties make the resulting rules and final tokens independent of iteration order. Differential full traces are the executable gate. Both builders retain expected constant-time lookup for ordinary inputs, but neither provides a constant worst-case time guarantee. `ahash` is an established noncryptographic hasher with randomized default state; its use here is an experiment on these prepared fixtures, not an assertion of universal speed or hash-flood resilience.

The route headers and map entries remain unique per logical owner/producer as before. There is no second corpus or full index; the two generic instantiations add binary code size, not duplicate live index memory. Builder state size and table growth may differ, so process RSS can change. `call_seconds`, `call_cpu_seconds`, immediate `train_vm_hwm_mib`, phase timers and deterministic work counters are reported with the same timing boundary as other radical variants. The `ahash` implementation may use hardware AES or a software fallback depending on architecture and compiler target features. Comparisons must retain the exact binary/source hashes, CPU affinity, rustc flags and host feature context. A speedup on one CPU does not prove a portable gain.

The parent 4 MiB W4 phase times motivate this isolation without measuring hasher cost directly: English owner initialization 0.0667 s, frequency reduction 0.1009 s and birth fill 0.0534 s; Chinese 0.0864 s, 0.0937 s and 0.0276 s. These phases also include scans, allocations and posting append, so the controlled call result is decisive. Tests run weighted, AA, adjacent and random reference cases under both modes. The exact candidate sequence and final token array must match the shared oracle on W1/W4 before performance comparison.
