# Rule-context aggregation with bounded sparse accumulators

`owned_context` copies the frozen `owned_grouped_inline` kernel. `--planner hash|context` defaults to `hash`; AA remains on the original exact parity path. The experiment changes only non-AA planning. It does not copy the corpus or pair index and does not change candidate selection, owner commit, posting representation or rule order.

For one selected rule `(a,b) -> Z`, a retained left neighbor `c` causes both old `(c,a)` to disappear and new `(c,Z)` to appear with the same weight and physical count. A single left-context accumulator records both effects and the new position chain. Two other families independently accumulate old right `(b,c)` decreases and new right `(Z,final_c)` births. `final_c` may be the new ID of an adjacent selected rule, so it cannot generally share the old-right counter. The original left-selected test still skips duplicate bridges. Every event uses the original weight and checked u64/u32 sums.

Each producer has a persistent sparse-set directory with three u32 cells per possible token ID. A directory cell points into a bounded vector of context entries. The entry stores its complete context/family index, so a stale directory index is accepted only if it is in range and still names the same context. Clearing the vector therefore invalidates previous entries without clearing the directory. A producer holds contexts for only its current rule: switching rule, filling the entry buffer, or finishing its job flushes groups to its existing owner route maps. Birth nodes remain the existing eight-byte nodes. A group keeps head and tail; flush links its tail to the route map's older head and installs the new head, preserving all positions across repeated flushes.

The directory covers the conservative whole-training bound `initial_lengths.len() + max_merges`. Its per-producer byte budget is explicit (`--context-index-bytes`, default 1048576). If the bound overflows, the 3-family index cannot fit u32, or the directory exceeds that budget, the entire training call uses the original hash planner and reports the fallback. `--context-entries` bounds the sparse vector (default 4096, allowed 1 through 65536). This is O(WV) vocabulary metadata under an explicit cap, not an unbounded per-thread pair index. For V=6000 and W=4, directory payload is 288000 bytes total; the maximum 4096-entry buffers add about 512 KiB on this 64-bit layout. Both payloads, construction time, hit counts and actual grouped route updates are reported. Allocation and initialization occur once inside the timed call; all buffers are dropped before it returns.

Non-AA rule task ranks are ordered, and each producer claims increasing task indexes, but correctness does not depend on monotonic rank: any rule change flushes the previous rule first. All producers finish and flush before apply, so no birth index survives the lifetime of its route output. Each scratch is exclusively borrowed by one producer job, independent of which physical Rayon thread runs it. The context-update methods are explicitly unsafe, with the ID-domain precondition proved at their only production call site; directory unchecked indexing is justified by the validated token-ID bound and the three fixed families; sparse-vector lookup still validates stale indexes and full context equality. There are no shared mutable accumulators or new atomic counters.

With E routed events and G flushed groups, planning uses direct directory accesses per event and owner-route hash updates per group; left-context groups replace two correlated per-event updates. Initialization costs O(WV) once, retained metadata is O(WV + WK), and temporary birth storage remains O(E) for the batch. Capacity flushes can reduce reuse; worst-case grouping does not reduce the number of route hash updates, while still paying direct-address overhead. Fallback, adversarial context order, small entry caps, weighted inputs, rank changes, adjacent selected rules and AA must all match complete serial traces. Speed and memory improvement remain to be measured.
