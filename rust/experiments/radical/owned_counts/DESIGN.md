# Counted owner deltas

`owned_counts` isolates a change to the `owned` trainer's merge-update path. Both variants use the same owner partition, exact conservative batch selection, dynamic position chunks, AA parity, initial index, position-only birth routes, lazy/eager heap policies, and apply→birth-decode barrier. This version replaces each routed `i128` frequency delta with `Delta { weight: u64, occurrences: u32 }` and gives newly eligible pair postings an exact initial capacity.

At the start of a batch, `fresh_start` is the ID about to be assigned to its first rule. Every old edge in the stable corpus has both IDs below that boundary. Every final born edge contains at least one fresh ID assigned within this batch. Owner reduction can therefore use the key itself to choose subtraction for old edges and addition for born edges. A pair key cannot receive both directions in one batch. Selected old keys have already moved out of owner maps and their routed updates are ignored. This argument depends on planning all rules against the same stable corpus and generating only final edges; it does not hold for an implementation that exposes transient intermediate edges.

Each route update adds an absolute edge weight and one physical occurrence using checked arithmetic. Weights come from the actual piece containing that edge, so uniform piece weights are unnecessary. A producer's local map and the owner's cross-producer map both check sums. The shared input validator limits the initial weighted edge total to `u64`, and all final live edges are a subset of that budget; each delta's weight fits `u64`. The corpus position bound makes a per-key physical count fit `u32`. The code still returns explicit overflow errors if either premise is violated.

For a new key at or above the frequency threshold, its owner allocates `Vec::with_capacity(occurrences)` once. After all endpoint writes join, the owner decodes routed `u32` positions from the final corpus and appends those that belong to eligible new keys. It verifies that the resulting vector length equals the counted occurrences. Old postings only lose frequency and never append. Below-threshold new keys are decoded for route integrity but allocate no persistent list. This does not remove HashMap, Vec header, or route-bucket overhead.

`delta_value_bytes` and `delta_entry_bytes` expose the target layout on the actual compiler: `Delta` should occupy 16 bytes, and the `(u64, Delta)` pair 24 bytes, compared with the old `(u64, i128)` pair's 32 bytes. `peak_delta_keys` and `peak_route_delta_capacity` report the summed producer route maps; the latter counts slots rather than allocator bytes. `owned_posting_len`, `owned_posting_capacity`, and `train_vm_hwm_mib` retain their meanings from `owned`: final retained positions/capacity and process peak during the timed training call. They are not a full allocation ledger. The first validation gate compares every rule, frequency, order, and final token against the shared serial oracle for both heap policies, including nonuniform and near-limit weights.
