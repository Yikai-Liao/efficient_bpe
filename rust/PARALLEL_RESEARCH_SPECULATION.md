# 把精确 BPE 当作有序、可推测的事务流

这是未实现的研究方案。与 [并行架构选项](PARALLEL_RESEARCH_OPTIONS.md)共用同一精确契约：每轮的胜出 pair、频率和平手次序，以及该 pair 在连续 token 路径上的左到右不重叠替换，都必须与现有串行训练一致。设计借用事务系统的**版本化读取、先准备后提交、按序认证**，但不把数据库论文的速度数字移植到 BPE。

## 为什么现有两道 barrier 之后仍是串行决策

一次 BPE 规则可看作事务 `T_r`：读取全局频率最大值、该 pair 的历史 occurrence 和各起点的前后 token；写入端点、几个受影响 pair 的频率、后继 occurrence、规则表与新 token 长度。当前 snapshot 实现已把同一 `T_r` 的验证和写入交给多个 worker，但 `T_{r+1}` 的身份要等 `T_r` 的频率 delta 全部归并后才能确定。`ABAB` 中两处 `AB` 的物理写不重叠，第二处的新左邻却是第一处的新 ID；连续语料 `ABCABCABCDEDE` 中 `AB` 与 `DE` 的写和符号都不冲突，`AB→X` 之后 `XC=3` 却会压过 `DE=2`。局部冲突检测不能替代全局优先级认证。

这个差别决定了可借用什么：

| 类比 | 能借用的机制 | 不能直接借用的前提 |
|---|---|---|
| [Calvin 的预定全局事务序](https://dsf.berkeley.edu/cs286/papers/calvin-sigmod2012.pdf) | 分开“决定顺序”和“按顺序并行执行”，让所有 worker 使用同一提交前缀 | Calvin 在执行前已有事务输入顺序；BPE 下一规则是前一规则执行结果的函数，不能预先排完整词表 |
| [Bohm 的多版本并发控制](https://arxiv.org/html/1412.2324) | 读稳定快照、把候选变更作为版本，而不在原语料上试错 | 其事务序可先决定；BPE 的新 pair 会改变后续候选身份，版本化本身不能认证赢家 |
| [Block-STM 的预定顺序加验证](https://arxiv.org/html/2203.06871) | 只提交与目标串行顺序一致的前缀；依赖失败时重做读集 | 区块交易的顺序是输入，BPE 只能对**猜测**的候选顺序做验证 |
| [Galois 的有序 worklist 与语义冲突](https://www.cs.cornell.edu/~kb/publications/Galois_PLDI07.pdf) | 同规则的非重叠 path contraction 可用局部语义冲突和重试 | BPE 的“更高频”是全局关系，远处新 pair 跃升不会出现在单纯空间冲突图中 |

这些是结构类比，不表示数据库的事务调度已给出精确 BPE 并行算法。[BatchBPE](https://arxiv.org/html/2408.04653)提供不同批量训练目标的启发，但其局部互不干扰条件不能保证此处要求的逐轮同序，反例见上文。

## 可证明的单调性与最小认证器

对一个已确定规则 `(a,b)→x`，其中 `x` 是从未使用的新 ID，每次替换只删去旧 token 间的相邻边，生成的新边都含 `x`。因此在该规则完成后，**所有仅由旧 ID 组成的 pair 的加权频率不会增加**；同一旧 pair 的历史 occurrence 列表不必追加新位置，只需在使用时过滤失效项。这一结论假设替换完整保留 `x`，且不越过永久 `0` 分隔符。它与 `AA` 是否重叠无关，但替换集仍要按左到右确定。

设快照中第二候选旧 pair 为 `q`。若 `q` 的每个 occurrence 与首规则无关，则 `f(q)` 不变，其他旧 pair 只能下降；**仍不能直接提交 `q`**，因为新 pair `(x,c)` 或 `(c,x)` 可能以更高频率出现。精确认证需要在首规则提交后：

1. 从已归并 delta 得到所有受影响旧 pair 的精确频率，并把新 ID pair 放入全局候选结构；
2. 用当前最大值与平手 key 验证 `q` 仍是赢家；
3. 重读 `q` 的候选起点、右邻及前后 token，核对预备 plan 的有效性和上下文；
4. 仅当上述均成立才给 `q` 分配正式下一 ID 并提交。失败则丢弃推测 plan，正常选新赢家。

可以试图提前认证：未受影响的旧 pair 分数精确，受影响旧 pair 的旧分数是上界，某候选的“旧分数减最多损失”是下界。每次首规则替换最多建两个新边，故一个新 pair 的粗上界不超过所选替换权重总和的两倍；这个界通常太松，因为第二候选频率本来就不高于首胜者。按前后邻 token 汇总的更紧新 pair 上界需要处理首规则的大部分 occurrence，接近实际 delta 归并工作。应实测证书成功率，不假设它会普遍跳过 barrier。平手时比较完整 `(frequency, key)`，不能仅凭频率间隙判断。

## 一个不复制全语料的有限窗口

保留一份权威 corpus、频率表、历史 occurrence 索引和 token 长度表。设窗口 `W=2…8`，只从当前 heap 取若干**候选**；这些候选还不是规则。worker 在只读已提交快照上预备各候选的有效 occurrence、左到右冲突摘要、前后文和频率 delta，把它们放入私有日志。日志只存触及的起点、边界 token、变更 pair key 与权重；不写权威 corpus，也不提前消耗正式 ID。提交器按顺序执行上一节认证，提交最长有效前缀，首个失败项及其后项全部撤销。撤销仅释放日志；没有原语料 rollback，也没有 `P` 份 corpus。

预备 plan 的位置有效性可在提交时重算 `pair_matches` 和上下文。新 ID 永不复用，因此同一物理起点从活的旧 ID 变成别的活 ID 后不会回到旧 ID；这个单调性可充当轻量 generation 信息。若要跳过重算，可另加块级 epoch，但它会带来 `O(N/block_size)` 元数据与共享写竞争；先测重新读取成本。只核对两个待合并 token 仍相邻还不够：前后邻变化会改变 delta 和后续 occurrence 起点。日志必须记录或重算前后文。对于 `ABAB`，第二处 plan 的左邻需从原来的 `B` 修正为前一次合并的新 ID；修不了就废弃该 plan。

空间上初始权威索引仍是 `O(N+M)` 级别的历史记录；推测额外空间为 `O(Σ touch(T_i))`，其中 `i<W`。高频候选可能触及 `Θ(N)` 位置，因此 `W` 为常数也可能产生 `Θ(WN)` 峰值。需要**总日志字节预算**（例如按现有索引内存的一小部分设上限），超过预算立即退化为单候选；不能只设置窗口规则数。计划还应按位置区间压缩 AA run 的奇偶摘要，而不是给每个重叠 `AA` occurrence 做独立可提交写。

若同时让多个候选在快照上准备，只读工作可以重叠；但后序候选的 plan 可能频繁因前序改边而作废。更激进的分支 overlay 能把前序推测端点和 delta 放入稀疏映射，再让后序读取预测状态，代价是更复杂的正确性证明、较多随机查表以及热点规则下接近整份 corpus 的日志。首版应只读预备、串行认证、并行执行已认证的同一规则，先测可复用工作比例。

## 依赖图和自适应窗口

一条规则内部，沿 token 路径的候选边形成 path matching 问题：`AA` run 的选择由最左端起算的奇偶决定；不同 run 可并行，跨区间 run 用前缀奇偶传递。不同规则之间，依赖分两层：局部 corpus/边界读写依赖，以及任一新 pair 可能抢走全局最高频的**优先级依赖**。后者把所有规则连成一条潜在有序链，所以只按位置建冲突图会错误地放大并行度。动态 ordered task graph 只有在认证器证明某些边不存在时才可提前提交。

建议窗口由真实有效率调节：连续若干轮候选认证成功、日志命中且新 pair 没有抢位时缓慢增大 `W`；`AA` 长 run、频繁平局/新 ID 回胜、上下文修正量大或日志接近预算时立即降到 1。记录 `prepared_candidates`、`committed_without_replan`、`wasted_plan_cpu_seconds`、`log_peak_bytes`、`winner_certificate_wait_seconds`、`plan_context_repairs`，并按规则轮数和被替换位置数分别加权，避免低频长尾的大量小轮掩盖热点阶段。将 certification CPU、heap 更新及必要 barrier 计入串行份额：若它们在目标语料上合计超过同环境单核总时长约 11%，四核整体 3×已被理想 Amdahl 上界否定；废弃推测和内存带宽争用只会进一步压低上界。

首个可证伪实验不需要实现完整事务引擎。用当前串行规则轨迹离线记录每轮前 `W` 个旧候选、下一真实胜者、新 ID pair 是否插队、候选上下文变化及计划大小。若连续输入上的中位可认证前缀仍约为 1，或高耗时轮的预测命中低，停止多规则推测，优先优化单规则的 path matching／pair 更新归属；若高耗时轮稳定存在长度至少 2 的可复用前缀，再做有界日志原型。离线分析给出**可用并行度上界**，仍不能代替同二进制的实际 `call_seconds`、内存峰值及完整规则指纹验证。
