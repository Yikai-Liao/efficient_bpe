# 实际重叠证书：独立 Rust 原型

`parallel_pair_owned_spatial` 在原分片频率内核上扩大严格按串行顺序执行的批次。实现位于 `src/ablation/parallel_spatial.rs`，从固定提交 `d6c02be` 的 `parallel_sharded.rs` 分叉；旧内核未被该实验修改。入口注册由主实验统一处理。

## 认证与工作界限

每轮从精确 owner 堆按频率降序、同频 key 升序租借连续候选，保留原内核的 256 项类型证书上限；遇到首个类型冲突后，再向后最多租借 64 项。遇到 AA 时，窗口在它之前结束；若 AA 是首项，沿用原来的全局左到右处理。最早 token 类型冲突给出原证书的保底宽度 `k0`。没有类型冲突时直接执行窗口。

需要尝试扩大时，各 worker 一次返回整个窗口在其本地索引里的历史列表长度。设保底前缀长度总和为 `H0`；探测窗口仅纳入后续连续候选，直到这些额外候选的历史长度将超过 `2H0`。预算按包含失效记录的真实列表长度计算，不按有效出现数计算。若下一候选超预算，保留 `k0`。探测会重读保底列表，所以单轮完整探测读取至多 `3H0`；保底列表在本轮被消费且旧 key 不会再生成位置，故整个训练额外探测历史读取不超过保底消耗总量的三倍。长度元数据每轮至多 `256 × worker_count` 个整数，单独计时和计消息。

探测 worker 只读稳定语料和本地位置索引，验证窗口内每个候选的**全部**历史起点。对于有效 `AB`，检查它的右邻 `C`；如果 `BC` 也在窗口，冲突截止为 `max(rank(AB), rank(BC))`。归约所有 worker 的最小截止后，只有截止之前的连续前缀进入原有规划、owner 归约和写入阶段。被截掉的候选归还租借堆，索引列表保持原样。没有 O(N) 临时标记，也没有 worker 语料副本。探测读取与实际规划读取各发生一次。

`SPATIAL_PREFIX_PROPOSAL.md` 给出这个充分条件的精确性论证：完整出现区间互不重叠，使每条旧规则的频率和替换位置保持不变；批中产生的新 key 能单射映射到一个排在整个前缀之后的旧祖先 key，fresh ID 在同频时也更晚。因此逐轮的 rule、频率、fresh ID 和最终序列应与串行完全一致。当前实现对 AA 维持单轮全局选择。

## 验证与计量

独立单元用例检查类型上可能冲突的 `AB`、`BC`：分处两个 piece 时证书允许宽度 2，实际 `ABC` 时截止宽度 1。`tests/spatial_prefix.rs` 再用完整训练核对规则、替换数、最终 token 和批宽；两项通过。严格 Clippy 通过。[完整轨迹归档](batch_results/pair-owned-spatial-v1/differential.json)的 80 次比较全部通过，覆盖 8 个随机及定向输入、1/4 worker、checked/unchecked，逐条 rule、频率、final token 和指纹与独立 Python 全量重算 oracle 一致。该轮未测 2 worker。

扩大、真实冲突和预算截断三种轮次计数可能在同一轮重叠。

`spatial_probe_visits` 是原有 `position_visits` **以外**的读取；英文它是保底历史长度的 2.73 倍，中文是 2.45 倍。探测中的 stale 也照预算计。英文省掉 14 批，规划墙钟少约 3.64 ms，但长度汇总与探测已占 12.08 ms；4 worker 的完整调用比原 pair-owned 慢 7.63 ms（约 9.2%）。中文只省 6 批，规划少约 0.52 ms，新增两个阶段占 8.25 ms；完整调用慢 11.08 ms（约 18.9%）。因此退步来自额外读取和同步超过批次减少的收益，**不是证书没有扩大批次**。`select_seconds` 还包含扩大候选租借与归还，不能把其增量全归给两个新阶段。RSS 与原 pair-owned 接近：英文四线程 +0.02 MiB，中文 −0.02 MiB，单次峰值差不宜解释为稳定节省。

当前不宜把 spatial 路线并入主线。若继续隔离实验，先只改探测：类型保底内部已保证无冲突，因此仅扫描保底之后的候选，并对其每个有效 `AB` 同时检查左邻 `(X,A)` 和右邻 `(B,C)`。任何新冲突都至少含一个扩展候选，此检查覆盖全部跨保底和扩展内部的重叠；预算、候选窗口与最终批宽可维持不变，能单独量出省掉保底重读的价值。之后再试单阶段局部预算：每个 worker 用本地 `H0` 限制其额外读取，在一次 Probe 回复里带回预算截止与冲突截止，省去 Measure 往返；但无保底位置的 worker 会更早截断全局前缀，需同时报告损失的批宽。两项都应先在独立原型上验证，再决定是否值得接入 pipeline 或 global posting 路线。
