# 利用一次出生的位置表做分级存储

这是尚未实现的方向，用来连接当前内存训练器与磁盘训练；不代表已经有严格
内存预算的外存算法。关键不是把整个语料换成 mmap，而是利用现有索引中已经
证明的性质：一个 pair 的全部出现只在初始状态或唯一出生批次产生，此后只会
失效。位置表可保留 stale 位置，不需要逐项更新。默认类型证书只查询频率，
直到该 pair 被选中才扫描其位置表；选中或退休后，这份表即可释放。

## 一个可以隔离验证的最小方案

频率表与候选堆继续驻内存，短 posting 保留 inline；较长 posting 在出生提交
结束后封存为磁盘 extent，owner 只持有位置数和文件偏移。选中时按有界块读取，
交给现有位置验证和非 AA 替换流程。文件保存旧位置，不保存会反复变化的 live
位图。任何 extent 必须写完并发布描述符之后，才允许下一批选择读取它；写入
失败直接终止私有训练状态。磁盘上的临时训练状态不需要每批做持久化承诺，
但若另加恢复功能，恢复协议及同步成本必须独立设计和计量。

设初始物理 token 数为 N，总替换数为 M≤N。每次替换至多产生两条新边，所以
初始位置与所有出生位置的总数至多 N+2M。若每份已封存 posting 只读一次，
位置载荷的累计写入和读取都是 O(N) 个 u32。这里的一次读取是默认类型证书下
非 AA 顺序消费路径的条件；AA 外部排序的额外读取和临时 run 要另计，不能把
这个读取界直接套给完整训练器。这**不等于 O(N/B) 次块 I/O**。
K 份短 extent 分散在不同页时，读取有 O(K) 次小 I/O 以及页放大。必须同时
记录实际读写字节、请求数、页缓存和临时文件峰值。短表留内存、顺序打包出生
extent、同批按文件位置合并读请求，才可能把理论载荷优势变成吞吐收益。

首个实验只替换较长的永久 posting 存储，保留当前语料和频率索引，报告其减少
的驻留载荷与新增 I/O。它不会解决以下内存峰值：初始索引构建、一次巨大批次
的 birth routes、AA 排序/Plan、频率表和候选堆。不能在这些对象仍不受控时把
实验称作“给定任意内存预算可训练”。

## 真正限制预算还需要什么

- **初始和出生建表也要可分块。** 当前先构建整份 Vec 再写盘，仅减少后续
  驻留，不减少构建峰值。可先把 `(key,pos,weight)` 写入有界分区日志，再按
  key 归约和封存位置表；分区仍放不下时需要继续划分或外部排序，其 I/O、
  缓冲和完整 u64 权重必须计入，而不能假设任意哈希桶都刚好放下。
- **非 AA 可流式，AA 需单独处理。** 非 AA 的历史位置可按块验证。AA 要保留
  全局 run 左到右 parity，不能在任意读取块内重置奇偶；现有 dense bitmap
  占 N 位，稀疏 fallback 又排序 H 个位置。严格预算版本需要外部位置排序或
  有序区段归并，并把跨块 run 摘要纳入协议。
- **区域快照只解决端点依赖。** 数值边界窗口与延迟写允许区域独占语料；它
  没有让区域内随机端点访问变成顺序 I/O。固定区域的 posting 投影顺序可帮助
  调度，但若直接在磁盘列表上做二分分区，仍可能产生额外随机读。位置目录若
  为每个 key 建 T 项又会有 O(KT) 空间，须采用只记录非空区段的表示并计量。
  现有 kernel 让 T 个任务同时借用 posting 子切片，不能仅换一个存储容器就
  得到有界读取；需实现流式分发或有界任务块，并限制所有在途块的总容量。
- **频率与堆仍可能是瓶颈。** 活跃 key 数 K 可随 N 增长，尤其带权语料的
  单次出现也能达到 minimum。因此驻内存的 O(K) owner/heap 是最小方案的
  明确边界。候选堆还会有 stale 项，不能仅数活跃 entry。
- **读次数依赖证书。** 默认类型证书不预扫 posting。按需邻接摘要至多多读
  一次，但预算式空间探测可能多次探查未选中的 key；不能将“一次读取”的
  分析直接套给所有已有变体。第一版应固定类型证书。

长度继续使用 u32，不回到 u8。跨越 2³² 个物理位置时，文件偏移 u64 也不能
自动扩大语料坐标域；需另设计块号与块内位置。第一版保留现有输入域，在一份
可复现小样本中对比全 RAM 与强制 spill 的完整规则/频率/最终 token，并用很小
的读取块迫使合并和 AA run 跨块。随后才测不同 spill 阈值的时间、驻留内存、
实际 I/O 与临时磁盘占用，判断有无值得进一步实现的甜点。
