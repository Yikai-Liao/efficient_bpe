# 更宽的精确 BPE 批次：三个待验证方向

目标仍是逐条保留串行的 `(pair, weighted frequency, fresh ID)` 顺序与最终 token。当前批次按精确的批前候选顺序取连续前缀；非 AA 规则 `(A,B)` 与已选规则发生 `B=下一规则左端` 或 `A=下一规则右端` 的**类型冲突**时就停止。类型冲突不一定意味着语料中有共享 token 的匹配。下面的方案只尝试证明实际匹配互不重叠，不能跳过一个未获证书的高优先级候选。

这里有两项共同的正确性条件。第一，非 AA pair 的每个活出现都在当前批前快照中被选中；若两个选中类型的所有出现不共享 token，它们的旧 pair 频率互不改变，任何本批新边都含 fresh ID。第二，对 `AB→Z` 产生的固定新 key，其每个加权出现可映射到一个旧边 `(L,A)`、`(B,R)` 或相邻匹配之间的 `(B,A)`；这些旧边的批前频率是新 key 的上界，同频时旧 ID 的 key 排序优先。沿批前精确堆顺序逐个审查且不越过失败候选时，若一个更早的旧祖先真能压过当前候选，它必须先被审查；若它已入批，却贡献新边，则它和先前匹配有实际重叠，违反空间证书。AA 仍独占一批：重叠 `AA` run 的全局左到右奇偶选择不由普通 pair 的邻接摘要解决。以上只解释**选择**；执行仍须先完成稳定快照规划，再写端点、归约完整频率和出生索引，下一次选择必须等提交完成。

## 邻接摘要为什么只需在 pair 出生时构建

初始 key 在初始语料出生。本项目每次替换分配全新的 token ID，所有新边都含本次 fresh ID，所以一个 pair key 的位置只在初始或某个出生批次形成，以后只会失效。一次替换若使两条活 pair 边**首次**相邻，变化区必含新边；两条都未改变的旧边不可能因中间 token 被合并而突然共享 token。因此，若 key `P` 与 `Q` 当前有相邻出现，较晚出生的 key 在其出生后的最终语料上必见过另一 key；后来发生的替换只能使这项关系消失，或引入一个更新的 key。初始同龄 key、同批出生的两个 key 都在各自出生时读同一稳定完成的语料，任取一方即可。

不必为每个 Entry 保存出生轮号。`age(key)=max(left_id,right_id)` 对不同批次严格随 fresh ID 增长；初始 key 的年龄均小于首个 fresh ID。同批 key 的大小次序虽然不代表先后，但其摘要都在**整批完成后**构建，任取年龄较大的那方仍安全。摘要中的旧邻居、已失效位置和 bit 碰撞只会产生假阳性，不能漏掉真实重叠。只对当前 eligible 的 key 查询；低于 `min_frequency` 的旧 key 不会因后续合并重新增加出现，故无须保留其摘要。

构建无需再次扫描全语料。初始 owner 建位置表时，对每个出现 `pos` 在已验证的单位长度语料中读其前/后邻边，并 OR 两个邻 key 的 bit。新 key 的 owner 在端点 apply 完成、遍历现有 grouped birth chain 填充 posting 时，利用最终 `corpus[pos-1]`、`pos+len(left)+len(right)` 和 sentinel 读邻边，同步 OR bit。一个新 key 的所有 producer 链都填完才允许下一次选择。即使邻 key 本身低频不保留，把它的 bit 放入摘要也只是保守。AA 规则的出生边按同样最终状态记录摘要，AA 本身在选择时仍不参与扩批。

选批时先做现有类型检查；若类型不冲突，直接接纳。若冲突，只检查与候选类型相冲突的已选 key：以较新 key 的 `neighbor_mask` 测较旧 key 的哈希 bit。每一对都为阴性才能接纳；任何阳性或摘要不可用就**在这个候选处停批**，不探查更低优先级 key。批内频率仍从 owner 的精确堆取得，摘要从不作为频率或新生 pair 的分数。选中 posting 在规划前照旧移出 Entry，摘要随 Entry 小标量移动；类型冲突但空间获证的规则仍用现有稳定快照的非 AA 规划/最终出生边协议。

一个容易犯错的方向是只查询较早的 key 的摘要。语料 `Y X A B` 中，执行 `AB→Z` 后，新 `(X,Z)` 与仍存在的旧 `(Y,X)` 共享 `X`；旧 key 出生时当然不可能记录尚不存在的 `(X,Z)`。查询旧摘要会错误地判定安全，查询较新 `(X,Z)` 的摘要才会发现冲突。另一个错误是只证明 `AB` 与低排名 `CD` 不重叠便跳过中间冲突候选：连续 `ABABABCD` 的批前 `BA` 频率高于 `CD`，执行 `AB` 后新 `ZZ` 可压过 `CD`。必须在 `BA` 处停止或给它真正的空间负证书，不能越过它。

## 最小 Rust 实验与退出条件

从冻结的 `owned_grouped_inline` 复制独立 crate，设同二进制 `--batch-certificate type|birth-neighbor64`，默认 `type`。先只加 `Entry.neighbor_mask: u64`、初始/出生时的上述 OR、年龄方向的选择检查和 `type_conflicts_examined / mask_negative_admissions / mask_positive_stops / mask_popcount / sketch_build_seconds / sketch_payload_bytes` 指标；不改 owner 数、heap、AA parity、频率路由或端点布局。比较 `type` 与 `birth-neighbor64` 的完整规则/频率/最终 token 轨迹、批次数和自身 W1/W4 完整调用，而不是仅看扩批宽度。定向测试应覆盖新旧 key 相邻、同批两个 fresh key 相邻、长 token、非均匀权重、bit 碰撞、AA singleton，以及高频新 `ZZ` 抢占。一个失败的摘要负证书必须使测试失败；阳性造成的保守停批允许存在。

先在小输入统计类型冲突中能给阴性证书的比例与掩码饱和度。若高频候选的 64-bit 掩码大多全满、批次数未明显下降，或额外索引/RSS 与 O(N) 邻居读取抵消收益，就停在设计和失败数据，不把误判率问题伪装成调参可救。若阴性证书确实减少同步轮次，再做 4 MiB 的同预算对照；任何速度结论仍需保留最佳直接串行绝对用时。
