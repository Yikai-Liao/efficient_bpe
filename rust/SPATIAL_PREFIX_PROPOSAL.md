# 用实际出现的重叠放宽精确批次证书

这是从当前语义推导的下一候选，尚未实现、未获得批宽或速度数据。当前 pipeline 改动先减少每批阶段数；本方案另问：是否可以让一批容纳更多严格按串行顺序执行的规则？

## 当前条件排除了什么

现有证书只看 token 类型：已选 AB 后，若下一个候选为 BC，立即停止，因为二者可能在 ABC 上重叠。这个条件不需要扫描位置，但即使语料中只有分开的 AB、BC，根本没有 ABC，也会停止。

对不含 AA 的连续候选前缀，可以用更弱的充分条件替换它：**前缀内所有有效 pair 出现的两个 token 区间互不重叠**。这里比较的是完整实际出现集合，不能只给每条规则挑一个无冲突子集，否则其频率或替换行为会改变。

## 为什么实际互不重叠已经足够

按批前精确频率及同频 key 顺序，考虑一个满足实际不重叠的连续前缀。

1. 任一规则的全部出现不被前面规则破坏，因此被轮到时仍有原来的精确频率，且会替换相同位置。
2. 任一批中新边都可以映射到它的批前邻接祖先：`(L,Zi)` 对应 `(L,Ai)`，`(Zi,R)` 对应 `(Bi,R)`，`(Zi,Zj)` 对应 `(Bi,Aj)`。单一新 key 的出现能单射映射到同一祖先 key 的出现，保持 piece 权重。
3. 产生该新边的祖先 key 不可能属于这个前缀。否则那条祖先边本身也是被选规则的有效出现，并与生成新 token 的出现重叠，与条件矛盾。
4. 祖先 key 因而排在整个连续前缀之后；新边频率不高于祖先的批前频率，同频时 fresh ID 又使新 key 晚于祖先。所以新边不能抢在前缀里的下一条规则之前。未选旧 key 的频率只会下降，也不会抢占。

因此前缀的完整规则、频率、fresh ID 顺序与逐轮串行一致。原有批末邻接规划器仍可使用，因为它需要的是实际匹配区间不相交。AA 暂时继续单独执行：它有重叠计数与左到右选取子集，不能直接套用上面的“全部出现”条件。

## 不分配全语料标记数组的检查

从精确候选序列取有界窗口，建 `pair key → 窗口序号` 小表。各 worker 只读检查窗口里的历史起点，丢弃失效记录。对于有效 AB 出现，读取右邻 token C，若 BC 也在候选窗口中，则发现一对实际冲突。两条规则的序号为 i、j，这个冲突要求前缀在 `max(i,j)` 之前结束。对所有冲突取最小截止序号，即得到该窗口中最早发生冲突的位置；没有冲突则整个窗口通过。

单看右邻就能覆盖每个重叠：它会从左侧那条被选候选的起点被发现。规则内的自重叠已经由禁止 AA 排除。该方法用候选表与每个 worker 一个局部截止值，不需要 O(N) 临时标记数组，也不需要先写入语料再回滚。

但它新增一次位置验证和一次归约，不能因为条件更宽就断言更快。第一版可只读验证、随后复用原规划器，明确付出第二遍读取；若缓存有效位置，需要另报 scratch 峰值。

## 必须限制推测工作

若每轮盲扫大窗口，迟迟未被选中的 pair 可能被反复扫描，破坏现有历史位置累计访问的好性质。可先计算原 token 类型证书得到的保底前缀，以及这些列表的历史长度 H0，再限制本轮额外窗口的历史长度不超过 βH0。取 β 为固定小常数，扩展失败也保留原前缀。

原前缀的 pair 本轮一定被消费，之后不会再新增该旧 key 的位置。因此各轮 H0 的总和受历史记录总生成量 O(N) 约束；固定 β 的探测预算也能保持 O(N) 额外位置访问量。这个界要求预算按实际扫描的历史记录计数，包含 stale，且取得长度元数据的工作也须计量；不是只限制候选条数。

实现前需解决如何廉价取得分片列表长度。若为此每个候选都往返全体 worker，会用新的消息瓶颈抵消批宽收益。可以随现有候选窗口命令一次性汇总长度并统一截断，但这又有阶段成本。只有测得扩大批次节省的同步超过额外验证、元数据和缓冲代价，才应纳入主线。
